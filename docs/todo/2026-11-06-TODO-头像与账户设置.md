# 待办：头像与账户设置

创建：2026-11-06 · 状态：待办 · 优先级：中

## 背景

主人提了四件事：图片上传的大小上限提高一些、新增头像、新增账户设置、新增历史头像。经过三轮拷问，需求已经全部拍板，结论在 [ADR 0050](../adr/0050-account-page-password-rename-and-deletion.md)（账号页）和 [ADR 0051](../adr/0051-photo-limit-50mb-and-avatar.md)（50MB 上限与头像），范围见 [scope](../requirements/scope.md) #42、#43。**还没开始实现**，这条待办跟踪实现进度。

## 可选方案

- **方案甲**：分三步实现、三次提交：先改 50MB 上限和后端内存写法（独立、风险最高、和头像无关）；再做账号页的昵称、改用户名、改密码、注销；最后做头像、裁剪框和历史头像 —— 代价：账号页的头像区要等第三步才有。
- **方案乙**：一次全部做完 —— 代价：一次提交太大，内存写法这一块出问题时不好单独回退。

➡️ 倾向：方案甲——50MB 那一步动的是所有上传都会经过的公共路径，单独提交、单独验证最稳妥。

## 待确认

无（需求已定）。实现时注意：裁剪框要在安卓壳的 WebView 里真机验证双指缩放。

## 更新记录

- 2026-11-06：创建，记录第一轮待拷问的问题。
- 2026-11-06：第一轮已答——餐照与日记图片上限提到 50MB；头像只在「我的」页页头显示；账户设置里放头像、历史头像、改密、改用户名、昵称、退出登录、注销账号，设了昵称就显示昵称；历史头像全部保留、可切回、可单张删除；头像占照片空间、不进相册；从「我的」页页头进入新的二级页；要做手动裁剪框（拖动＋缩放）。方案甲已选定。第二轮待答：识别的 5MB 是否不变；50MB 与后端 256MB 堆的内存风险；昵称规则；改用户名、改密、注销的细节；删除头像的去处；裁剪后存什么；「账户」还是「账号」。
- 2026-11-06：第二轮已答——识别 5MB 不变；50MB 靠后端边收边写盘与降采样解码扛住，不加堆；「我的」页页头优先显示昵称，首字母也取自昵称，管理端只在用户列表加昵称列；昵称 1～20 字、可重名；改用户名需当前密码、旧名立即释放、缓存改按用户 id 区分；改密需旧密码、其他设备下线（加令牌版本号）、agent 令牌不受影响；注销需密码＋手打用户名、立即彻底删除；删头像进回收站、可「不用头像」、历史不限张数；统一叫「账号」。**改动**：裁剪后还要保留原图，从历史切回某张须重新裁剪。第三轮待答：原图怎么存、切回后历史里怎么排、当前头像能否重新裁剪、历史里显示原图还是裁剪结果。
- 2026-11-06：第三轮已答——原图原样保存、占空间不进相册、删除时与裁剪结果一起进回收站；切回重裁后覆盖原来的裁剪结果并移到最前；裁剪框默认停在上次的位置，当前头像也能重裁；**历史列表在方形格子里完整显示原图**（不显示裁剪结果）。需求全部拍板，写成 ADR 0050、0051，scope 补 #42、#43；本条转为跟踪实现。
