# 待办：饮食趋势图可缩放时间轴

创建：2026-10-13 · 状态：已解决 · 优先级：中

## 背景

主人把饮食趋势图的形态从「7 天 / 30 天 / 1 年三个固定档位」改成**一根可缩放时间轴**：以精确日期为横轴、双指捏合缩放、单指按住滑动显示准星与数值、横轴可见的日期数量设上限以免混乱、缩放时「一个像素对应多少天」随之变化且不能有明显卡顿。

现状（细节看代码，此处不复述）：趋势图是手写 canvas 自绘，固定 30 天，坐标是一套写死的设计常量，x 轴按数组下标等分，横轴标签固定取固定数量的点，每次整帧重绘，没有任何手势；后端趋势接口的天数是「截至今天的最近 n 天」并有硬上限。

工作量评估：**中等偏上——等于把趋势图绘制层重做一遍**。后端只需放开上限或改出「起止日期」入参（范围查询的 SQL 与索引已就绪，无需数据迁移）；前端则要把坐标常量、下标等分、固定标签、整帧重绘整体替换，并新增手势与准星层。最大风险是**坐标系与手势单位不一致**——绘制用的是写死的设计坐标，而 H5 canvas 透传给业务层的触点是画布本地 CSS 像素，再叠上 hidpi 的 DPR 缩放；不统一会让准星错位、缩放锚点漂移。

## 可选方案

- **方案甲：继续手写 canvas，抽出公共趋势组件重建绘制层** —— 代价：绘制层重写；好处是零新依赖、与身体页体重趋势同源同口径。
- **方案乙：引入 echarts 或 uCharts** —— 代价：约 1MB 体积，uni-app 下还要过 renderjs；好处是缩放与提示框现成可拿。

➡️ 倾向：**方案甲**。项目现在一个图表库都没有，为三条折线加一根准星引入重量级依赖不划算；且身体页已有同款手绘趋势，两处收拢到同一组件符合单一信息源纪律。
