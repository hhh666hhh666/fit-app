# 待办：设计变量真相源路径写错

创建：2026-10-12 · 状态：已解决 · 优先级：中

## 背景

`AGENTS.md` 的「改前端 UI 时的入口」与 `.codebuddy/rules/design-tools.md` 的硬约束段都写「设计系统的唯一真相源是 `frontend/src/styles/tokens.css`」，但**该文件与 `frontend/src/styles/` 目录都不存在**——真实文件是 `frontend/src/uni.scss`，且 `docs/design/前端.md` 开头也是按 `uni.scss` 写的。两处「真相源」指向一个不存在的文件，改颜色的人会先撞一次空；`DESIGN.md` 的「从 tokens.css 派生」同样需要核对。

## 可选方案

- **方案甲**：把 `AGENTS.md` 与 `.codebuddy/rules/design-tools.md` 里的 `frontend/src/styles/tokens.css` 改成 `frontend/src/uni.scss`，并核对 `DESIGN.md` 的派生说明 —— 代价：`.codebuddy/rules/` 是常驻规则，改它等于改 AI 的行为约束，宜由主人 过目。
- **方案乙**：反过来把设计变量真的迁到 `frontend/src/styles/tokens.css`（新建 CSS 变量层、替换 `uni.scss` 的 SCSS 变量） —— 代价：动全站样式与构建链，收益只有「文件名更通用」，不划算。

➡️ 倾向：**方案甲**。实现本来就是 `uni.scss`，是文档写错了、不是代码写错了；方案乙等于拿大改迁就一句写错的文档。

## 待确认

无（2026-10-23 主人批准改常驻规则，按方案甲结案）。
