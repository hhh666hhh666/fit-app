# 待办：云端网页版 CORS 误判

创建：2026-10-26 · 状态：已解决 · 优先级：高

## 背景
云端为 apk 配了 `FITAPP_CORS_ALLOWED_ORIGINS` 后，网页版登录 `403 Invalid CORS request`：TLS 在宿主 nginx 终止，后端不认 `X-Forwarded-Proto`，把同源的 `https://` 请求判成跨域。浏览器同源 GET 不带 `Origin` 所以不受影响，POST/PUT/DELETE 全中招。代码已修（`server.forward-headers-strategy: native`，本机已验证），**还没发版上线**。

## 可选方案
- **方案甲**：发版带上该配置 —— 代价：需宿主反代确实设了 `X-Forwarded-Proto $scheme`，否则仍 403。
- **方案乙（应急）**：服务器 `.env` 的白名单追加 `https://fit.11-2.cn` 并重启后端 —— 代价：多一个域名写死在配置里，治标。

➡️ 倾向：方案甲；上线后若仍 403，先查宿主反代是否传了 `X-Forwarded-Proto`，急用可先上方案乙。

## 待确认
- 宿主（宝塔）反代是否设置了 `X-Forwarded-Proto`。
- 上线后自查：`curl -X POST https://fit.11-2.cn/api/auth/login -H 'Origin: https://fit.11-2.cn'` 不应返回 403。

## 更新记录
- 2026-10-26：定位根因并改代码，待发版验证。
- 2026-10-26：随 **v0.28.4** 上线，线上 curl 验证同源 https → 200、他源 → 403，结案。宿主反代确认有传 `X-Forwarded-Proto`。
