# 待办：识别用量统计

创建：2026-11-15 · 状态：已解决 · 优先级：中

## 背景

主人要在「识别用量」那里加一个统计入口，至少能看金额汇总和总 token。现状：「我的」页小卡只露累计 token 与请求次数，明细列表逐条不带钱，金额只在单条识别详情里按 DeepSeek 价目估算（[ADR 0054](../../adr/0054-recognition-price-deepseek.md)）。2026-11-15 拷问已拍完，下面是定下的设计，**等主人确认共识后实现**。

## 已拍定的设计

- **入口**：「识别明细」页顶部加一张摘要卡，固定按「全部」统计，一行「估算 ¥… · … token · … 次」，点进新页「用量统计」（`pages/recognition-log/stats`）。「我的」页小卡与明细列表**不变、不露金额**；无记录时不出摘要卡。
- **范围**：只看本人的记录；管理端的全站汇总仍挂在[管理端后续](../2026-11-04-TODO-管理端后续.md)。
- **统计页内容**：
  1. 合计：估算金额（另拆高峰／空闲各多少）、总 token（输入未命中／缓存命中／输出，另列「其中思考」）、请求次数（成功／失败）
  2. 平均每次：token、金额、耗时
  3. 缓存命中率＝缓存命中 ÷ 输入
  4. 按模型拆（按记录里的原样模型名，不合并别名）：次数、token、金额；非 DeepSeek 的金额写「未计价」
  5. 按入口拆：营养成分表入库／记一餐 AI 识别／未记录（老记录）
  6. 按日趋势图：复用 `FtTrendChart`，图上分段「金额／token／次数」（默认金额，只算 DeepSeek）；**跟随顶部范围**（「全部」从第一条记录那天画到今天，可缩放平移）；没记录的天补 0、日期连续；按请求发出的时刻、北京时间分天；气泡金额用统一写法；不做全屏
- **时间范围**：顶部分段「全部／本月／近 7 天」；北京时间；「本月」＝当月 1 号 0 点起，「近 7 天」＝今天加前 6 个自然日；都按**请求发出的时刻**划（与峰谷判断同一时刻）。空范围给空态「这段时间没有识别记录」，切换仍可用。
- **金额口径**：只合计 DeepSeek 的记录，注明「另有 N 次（M token）用的是非 DeepSeek 模型，未计价」；失败的调用照算钱与 token（与流水口径一致）；末尾注「按官方价目估算，以 DeepSeek 账单为准」；范围里有放假表没覆盖的年份时注一句「某年放假安排未录入，节假日只按周末判断」。
- **金额写法**（统计页、摘要卡、详情页三处统一，抽成 `utils/format.ts` 的公共函数）：只用 `¥` 符号，不写「元」；一元及以上两位小数（`¥12.34`），不到一元四位小数（`¥0.0064`），不到万分之一元写 `<¥0.0001`；**去掉详情页的「约多少分」**。
- **在哪算**：后端新接口 `GET /api/food-recognition/stats?range=`，按范围取轻量列（不带请求体／响应体／原文），逐条调 `DeepSeekPricing.estimate` 累加；同一接口返回 `daily` 序列（每天金额、token、次数），前端不另请求、不聚合；数据量小，不加缓存、不建汇总表。
- **文档**：不新开 ADR，在 ADR 0054 末尾追加后续注记；`CONTEXT.md`「识别用量」词条改掉「只有单条详情给价格」那句，不新增「用量统计」词条；前端与数据模型设计文档、范围、更新日志随实现同步。

## 可选方案
