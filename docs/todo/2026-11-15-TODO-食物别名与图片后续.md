# 待办：食物别名与图片后续

创建：2026-11-15 · 状态：待办 · 优先级：中

## 背景

食物别名、食物图片和新的搜索排序已经实现（[ADR 0056](../adr/0056-food-search-ranking-and-aliases.md)、[ADR 0057](../adr/0057-food-image.md)），还剩三件事：

- **第一批预置别名还没进线上库**：别名表 `scripts/preset-data/aliases-zh.tsv`（约 150 条）已起草，本地按全流程导入过一遍。按 ADR 0049，线上要走管理端：导出预置 JSON → `merge-aliases.py` 合并 → 预检 → 导入。导出和导入要用主人的管理员账号，所以要主人在场。
- **真机没验收**：裁剪框的方形预览、列表缩略图、详情页大图只在桌面浏览器的手机尺寸下看过，还没在安卓壳里试拍照和相册选图。
- **管理端没有裁剪框**：给预置食物上传图片时只能居中截取，要换取景只能先在本机裁好再传。

## 可选方案

- **别名导入**：发版后由主人在管理端导出预置食物交给 AI，AI 合并后交回导入文件，主人先预检、再导入 —— 代价：一次来回，预检能看到「更新 N 条、新增 0 条」再决定。
- **管理端裁剪框**：给管理端补一个桌面版裁剪框 —— 代价：要再写一个组件（App 的裁剪框是 uni-app 组件，管理端用不了）；目前给预置配图的需求很少，暂不值得。

➡️ 倾向：别名按上面的流程尽快导入；管理端裁剪框等真有成批给预置配图的需要时再做。

## 待确认

- 主人审一遍别名表，删掉或改掉不认同的叫法。
- 真机验收：拍照 / 相册选图 → 裁剪 → 列表缩略图 → 详情页大图；「复制为自定义」带图。
