# 待办：餐照缩略图方向

创建：2026-11-06 · 状态：待办 · 优先级：低

## 背景

做头像时发现：服务端生成缩略图用的是 ImageIO，它不看 JPEG 的 EXIF 方向标记。有损三档在前端经 canvas 重编码，方向已经摆正，不受影响；但「无损」档直传原图，手机竖拍的照片在相册和列表里的缩略图会是横的，点开原图（浏览器会按标记摆正）才是对的。头像那一路已经按 EXIF 摆正（`account/image/AvatarImages`），餐照和日记图片还没有。

## 可选方案

- **方案甲**：缩略图生成改用 `AvatarImages` 那套「读方向 → 只解需要的块 → 摆正」，餐照、日记图片共用；老图不重算 —— 代价：老的无损竖图缩略图仍是横的，要的话另写一次性脚本重算。
- **方案乙**：同甲，再加启动时一次性重算全部无损原图的缩略图 —— 代价：多一段只跑一次的搬运代码。

➡️ 倾向：方案甲，老图数量很少，真遇到再手动删了重传。

## 待确认

主人平时用不用「无损」档：不用的话这条可以一直放着。
