# 待办：餐次 AI 识别后续

创建：2026-11-09 · 状态：待办 · 优先级：中

## 背景

记一餐的「AI 识别」已实现（[ADR 0052](../adr/0052-meal-ai-recognition-temporary-entry.md)），但本地没有 API Key，只用模拟草稿验过弹层与保存，**真实照片的识别效果还没验过**。另外条目从这次起记下了钠，但界面上哪里都还不显示钠。

## 可选方案

- **上线后验证**：拿几张真实饭菜照片和营养成分表在 App 里试，看估算是否离谱、留空是否合理，必要时调 `MEAL_PROMPT` —— 代价：每次几分钱以内的 token。
- **钠的展示**：在条目副标题或饮食页当日汇总里加钠 —— 代价：首页四环与趋势的口径都没有钠，要先定放在哪。
- **识别价格的年度维护**（[ADR 0054](../adr/0054-recognition-price-deepseek.md)）：`DeepSeekPricing` 里的放假日表只录了 2026、2027；国务院一般在 11 月公布下一年的安排，到时要补。DeepSeek 调价时加一版价目、写上生效日，不改旧版 —— 代价：每年一次几分钟。
- **临时条目存进食物库**：在弹层里加「同时存进食物库」 —— 代价：表单只有 4+1，存进去的食物缺其余营养项；主人这次明确要「临时」，没有需求前不做。

➡️ 倾向：上线后先做真实照片验证（这是唯一的硬缺口）；放假日表 2027 年 11 月补 2028 年的；钠的展示等主人说要看再定位置；存进食物库暂不做。
