# 计划卡的点击语义：先预览再开练

Status: accepted

需求：「我的 → 训练计划」里点计划卡**不要直接开始训练**。现状是整卡 `@click` 直接 `navigateTo` 进会话页——想看一眼计划内容没有入口，误触的代价却是当场开一场训练；而且这一跳**没带 `fresh=1`**，本机若有未结束的会话，点任何计划都会静默接续那条旧会话（点 A 计划进了 B）。

## Considered Options

- **保持整卡直接开练**：否——误触代价过高，且计划内容不可预览。
- **新建只读计划详情页**：否——要多养一条路由、返回栈与登录守卫，信息量与编辑页高度重复。
- **点卡片只弹「开始训练？」确认框**：否——防住误触，但主人要的「先看清这个计划练什么」没实现。
- **整卡弹底部预览弹层（动作清单＋逐组目标），底部一个「开始训练」**（选定）。

## Consequences

- 弹层只放「开始训练」与「先不练」；**编辑入口仍只有卡片右上那个「编辑」**，不重复设置低频入口。
- 逐组目标的念法与编辑页、会话页共用 `utils/plan-target.ts`，不在弹层里另写一套。
- 点「开始训练」时若本机有进行中的会话，复用 ADR 0020 的「继续上次 / 开新的」确认；**开新会话必须带 `fresh=1`**——这是本次顺带修掉的静默 bug。
- 弹层里打开详情要拉一次 `GET /api/plans/{id}`：快速连点不同卡时，旧请求回来不得覆盖新选中的计划。
- 卡片右上「编辑」用 `@click.stop`，避免点编辑又触发预览弹层。

> 关联：ADR 0016、ADR 0020、ADR 0031
