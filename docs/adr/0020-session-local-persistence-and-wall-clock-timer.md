# 训练会话本地持久化、墙钟净计时与返回＝最小化

Status: accepted

需求是「返回主页、退到后台、甚至把 App 从最近任务划掉之后，训练还要继续、计时还要准」。现状两头都不成立：组次是会话页的页面局部状态，离开页面即清零；计时是每秒 `+1` 的累加器，而退到后台后安卓 WebView 会把页面定时器限速甚至冻结，累加值必然少走。[ADR 0011](./0011-session-early-finish-and-leave-guard.md) 当时正因为会话不持久化，才把返回键定义成「离开即丢弃」并加了一道确认。本次把训练会话升级为**本机持久化的会话对象**：开始时刻与暂停区间都记成时间戳，显示时现算；返回键＝最小化，首页给一个回程入口。

## Considered Options

- **会话只存服务器**（新增「进行中会话」表 ＋ 增量保存接口）：否——每勾一组发一次请求，网差就卡手；加表、加迁移、加接口成本最高，而「换手机接着练」在自用单机场景价值≈0。
- **本机存储 ＋ 服务器草稿双写**：否——两份数据对不上时还要再定一套仲裁规则，为几乎不会发生的跨设备续练换一处长期复杂度。
- **沿用「每秒累加」的计时器、只补持久化**：否——后台被限速是系统行为，改不了；累加值照样少走，正是本次要修的「计时不正确」。
- **返回时弹一次「继续训练 / 结束训练」**：否——多一次点击，只换来更显眼，而首页横幅已经足够显眼。
- **保留「离开即丢弃」的离页确认**：否——数据不再会丢之后，防误触的确认失去了存在理由，与该需求直接矛盾。
- **本机持久化 ＋ 墙钟净计时（开始时刻与暂停区间记戳、显示时现算）＋ 返回＝最小化、不做离页确认，首页给「训练进行中」横幅**（选定）。

## Consequences

- 新增本机存储项，读写统一收在 `frontend/src/utils/session.ts`；会话在每次变更、离开页面、页面隐藏时各存一次。进程被杀、从最近任务划掉、退到后台都不丢；只有手动「清除数据」或卸载才会丢。
- 计时口径：`净时长 = 当前时刻 − 开始时刻 − 暂停合计`。定时器只负责重绘、不参与累加，因此后台被限速多久都不影响正确性。后端 `workout.duration_sec` 收的就是这个净时长。
- 返回键 / 浏览器后退＝**最小化**：会话留在本机，首页底部「开始训练」按钮正上方出现「训练进行中 · mm:ss」横幅，点它回会话页。**只有「结束训练」才收尾**——0 组与未完成组的确认沿用 [ADR 0011](./0011-session-early-finish-and-leave-guard.md) 与 [ADR 0010](./0010-session-free-switch-and-early-finish.md) 的口径。
- **取代 [ADR 0011](./0011-session-early-finish-and-leave-guard.md) 的「离页即丢弃 ＋ 网页层守卫拦返回键」**。0011 的其余结论不变：任意时刻都能结束、0 组不发请求、不加页内「放弃训练」按钮、后端 `@NotEmpty` 只作防脏数据闸。0011 里「落地前必须真机验证守卫」那条前置随之作废。
- 会话**不设过期**：一条进行中的会话会一直留着。点「开始训练」时若已有它，此刻才弹一次「继续上次 / 开新的」，文案写明开新训练会让未保存的组次丢失；重开 App **不自动跳回**会话页（自动跳会打断「只想查个记录」的意图）。
- 已知遗留（本卡不解决）：本机存储不跨设备；手动清应用数据会丢掉整条进行中的会话。

> ⚠️ **后续（2026-10-24）**：首页「训练进行中」横幅随设计语言「晴窗」取消，回程入口改为底栏中间圆钮（进行中时显示为「继续」），四个主页面都有；点一下直接继续，「继续上次／开新的」二选一改为**长按**这颗圆钮弹出。见 [ADR 0041](./0041-design-language-qingchuang.md)。

> ⚠️ **后续（2026-10-31）**：「开新的会丢掉未保存的组次」改为进回收站，可恢复成进行中的会话（[ADR 0047](./0047-trash-snapshot-table.md)）。
