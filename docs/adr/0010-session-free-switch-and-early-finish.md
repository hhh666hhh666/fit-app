# 会话页动作自由切换与结束前未完成校验

Status: accepted

[ADR 0007](./0007-session-set-flow-and-target-weight.md) 把会话页定为「一次只显示当前动作、全组完成自动切下一动作、『更换』＝切到计划里的下一个动作」。实际训练常是**交错进行**的——先做卧推第一组、再做划船第一组、回头做卧推第二组……顺序推进的交互逼着用户要么打断节奏去点「更换」、要么把不相邻的组塞进同一动作。本次把动作切换放开为**任意跳转**（顶部动作分段条），并把「结束训练」加上**未完成校验**：只要有任意动作的任意组没勾，就先弹一次确认，避免误触把半截训练提交上去。

## Considered Options

- **维持顺序推进（不动）**：否——交错训练是常态，顺序交互要么打断节奏、要么诱导用户记错组（把 A 的第二组记成 B 的）。
- **「更换」扩成「换成任意动作」（替换而非切换）**：否——要额外定义「被换掉的已记录组怎么办」，连带语义最重；而用户的诉求只是**跳过去**，不是把当前动作从计划里替掉。
- **顶部动作分段条 ＋ 任意切换，保留「全组完成自动切下一个未完成动作」**（选定）：既满足交错，又不丢掉「练完一个动作自然过渡」的省心；完成一个动作后不再盲切下一个、而是切到**下一个还没做完的**，避免跳到已完成动作上。
- **结束训练不校验、直接提交**：否——有未完成组多半是漏勾或想中途收工，静默提交会让「没勾的组等于没练」变成用户的意外；弹一次确认成本极低。
- **结束训练直接拦截、必须全勾才能结束**：否——训练可能因时间/状态提前收工，这是合理需求；只提醒、不阻断。

## Consequences

- 会话页新增顶部动作分段条（`chips`）：每格显示动作名与 `已完成组数/总组数`，当前格强调、已完成格画勾；点任意格即切换，已勾的组**跨切换保留**（状态挂在 block 上，不随视图销毁）。
- 全组完成的自动切换语义由「下一个动作」改为「下一个**未完成**动作」（环形查找）；都完成则提示「全部动作已完成，可点『结束训练』」。原「下一个动作：X / 更换」行移除，「添加动作」占位保留。
- 「结束训练」在**有未完成组**时先 `showModal`：「提前结束训练？还有 N 组未完成，确定现在结束吗？未完成的组不会入库。」确认才提交，取消则留在会话页继续。未完成的组一律不入库、不写空值。
- 组次提交口径不变：仅提交已勾的组（`WorkoutCreateDTO.blocks` 仍是数组，提交侧零改动）。
- 计划内的**任意替换**（换成计划外动作）与**组级撤回/回看**仍未做——见 [会话页临场编辑能力待办](../todo/2026-10-12-TODO-会话页临场编辑能力.md)。
