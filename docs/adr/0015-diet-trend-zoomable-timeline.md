# 饮食趋势改为可缩放时间轴（手写 canvas 重做绘制层）

Status: accepted

趋势图此前是固定 30 天、坐标写死、按数组下标等分的静态 canvas，只能切五个指标。主人要的是**一根可缩放的时间轴**：以精确日期为横轴、双指缩放、单指按住看准星数值，且在竖屏与横屏下都有明确的可读上限。这等于把绘制层重做一遍。

## Considered Options

- **保留 7 天／30 天／1 年三个固定档位**：否——主人改要"自由缩放、精度联动"。
- **单屏最多看约一个月、靠平移回看历史**：否——主人权衡后取「单屏最多看一年」，接受长区间点密，并靠绘制抽稀与准星按天吸附来缓解。
- **长区间自动按周聚合**：否——缩放时粒度会暗中跳变，用户不知道"一个点代表几天"；与"以精确日期为横轴"相冲。
- **引入 echarts／uCharts**：否——约 1 MB 体积、uni-app 下还要过 renderjs；本项目现在没有任何图表库，身体页的体重趋势也是同款手写。
- **手写 canvas 重做绘制层（真实像素视口 ＋ 跟随刷新率重绘 ＋ 长区间抽稀）、抽公共组件、进页面一次性拉全量并缓存**（选定）。

## Consequences

- 坐标由"写死的设计常量 ＋ 按下标等分"改为"**真实像素视口 ＋ 日期到像素的连续映射**"，并显式处理 DPR。**这是本次最大的工作量与风险来源**：H5 canvas 透传给业务层的触点是画布本地 CSS 像素，与绘制用的设计坐标不是一把尺子；不统一会让准星错位、缩放锚点漂移，必须真机标定。
- 手势：**单指按住滑动 ＝ 准星**（显示该天数值、抬手淡出）；**双指捏合 ＝ 缩放**；**双指拖动 ＝ 平移**。缩放边界：单屏最少 3 天、最多 365 天；横轴日期标签最多竖屏 6 个、横屏 12 个；数据窗口 ＝ 全部历史。
- 后端：趋势接口由"最近 n 天"改为支持**起止日期**（范围查询的 SQL 与索引已就绪，无需数据迁移）。
- 绘制改用跟随屏幕刷新率的画法，并对长区间抽稀，避免连续手势掉帧。
- 抽成公共趋势组件，**身体页的体重趋势一并接入**，旧的写死坐标绘制退役——绘制层只留一份。
- 全屏按钮打开铺满的浮层，内部保留五个指标切换。
- 横屏：H5 无权限主动转屏，只能靠设备旋转自适应（竖屏与横屏的标签上限不同）。
