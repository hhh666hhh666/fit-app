# 计划目标按组设置（每组各一份次数与重量）

Status: accepted

需求：编辑训练计划时，同一个动作的**不同组**要能设不同的次数与重量（如 12 次 60kg ／ 10 次 65kg ／ 8 次 65kg）。现状是 `plan_exercise` 上一份 `target_sets`／`target_reps`／`target_weight`，整个动作共用；训练页按 `target_sets` 铺 N 行、N 行拿同一份值，计划里存不下差异。训练记录侧 `workout_set` 本来就是每组一行，执行侧不需要改，缺口只在计划侧。

## Considered Options

- **JSON 列存 `sets` 数组**：否——要手写类型处理器，绕开 Flyway ＋ MyBatis-Plus 的现有范式，且丢掉字段级校验。
- **`target_sets` 仍当真源、子表只存「与默认值不同的组」**：否——两套真源必然漂；「3 组只填了第 2 组」会变成合法态，预填逻辑要写一堆回退分支。
- **固定列 `reps_1`…`reps_5`**：否——组数上限被写死，加组就得改表。
- **弹层保留「组数／次数／重量」三个汇总输入，再挂一个「逐组微调」展开区**：否——两层结构让人分不清哪一层才是最终存下来的值。
- **填了组数就要求每组次数必填**：否——「只记次数、重量临场定」是真实用法，得允许单组某一项留空。
- **新增子表 `plan_exercise_set` 每组一行 ＋ 组数＝行数**（选定）。

## Consequences

- 新表 `plan_exercise_set`（迁移 V26）：一行一组，按组序排列，持有该组的次数与重量。**组数的唯一真相是子表行数**；`plan_exercise.target_sets` 降级为冗余列，写入时与行数同步（列表页的 `EST. VOLUME` 仍读它，不必每次 join 子表）。
- `plan_exercise.target_reps`／`target_weight` **保留不删**，语义改为「新加一组时的默认值」——不保留的话，主人加一组还得从空白开始填。
- 迁移要把现存计划回填：按 `target_sets` 展开成 N 行、每行填同一份 `target_reps`／`target_weight`。不回填等于现存计划的预填行为静默消失。
- 编辑交互：目标弹层从三个输入变成**逐组列表**（每组一行：次数／重量）＋ 一个「组数」输入框控制行数（改组数即增删行）＋ 一个「整组填充」（把第一行刷到所有行）。组数留空＝不设目标（子表 0 行），与今天一致。
- 训练页预填改为「第 i 行取子表第 i 行」；子表为空时仍铺 1 行空值（不变）。
- 计划卡摘要文本：各组值全同则折叠成「3 组 × 12 次 · 60 kg」，不同则列全「3 组 · 12/10/8 次 · 60/65/65 kg」。
- 保存仍是**整体删除重插**（`PlanService.update`），子表随之级联插入，不需要 diff 逻辑；这也让「清空目标」天然可行。
- 会话页「已勾的组永远是连续一段」（[ADR 0021](./0021-session-set-order-and-undo.md)）不受影响——逐组目标只是预填值，仍然是默认值不是约束（[ADR 0007](./0007-session-set-flow-and-target-weight.md) 的结论保留）。
- 实现时要跟着改：`docs/design/数据模型.md`（新表与 `target_*` 语义）、`docs/design/API.md`（`PlanSaveDTO`／`PlanDetailVO` 加组数组）。
