# 首页「上次训练」卡的成绩位：爬楼给块合计、底部给消耗

Status: accepted

需求：首页「上次训练」卡里，爬楼要显示层数；卡的底部不要再是总容量。现状是动作行写死「重量 kg × 次数」，爬楼行显示成「0 kg × 1」（占位值），底部只有「总容量 X kg · N 分钟」，纯爬楼场次则「总容量 —」——两个位置都没把爬楼的信息露出来。

[ADR 0023](./0023-volume-metric-scope-and-display.md) 当初要求首页卡按容量口径显示，本卡**只改首页这一张卡**的展示口径，不推翻该卡在详情页／汇总页／日志列表的结论。

## Considered Options

- **只改行值（爬楼行显示层数），底部维持总容量**：否——改一半；纯爬楼场次的底部仍是「总容量 —」，等于卡片最显眼的位置空着。
- **爬楼行也沿用「最后一组」**：否——层数是整场的累计量，没有「最后一组更有意义」这回事；力量动作才靠最后一组看渐进超负荷。
- **混合场次底部同时给总容量与总层数**：否——一张小卡里两个「成绩位」互相打架，读的人不知道该看哪个（ADR 0025 已定「有力量动作 → 容量」的优先级）。
- **爬楼行＝该块各组层数合计；底部＝消耗（手填，未填写「—」）＋ 时长**（选定）。

## Consequences

- 爬楼行的值＝该动作块 Σ 各组层数（如「112 层」）；层数全为 NULL 的历史场次显示「—」，不反推。力量行仍是「重量 × 次数」的最后一组。
- 底部固定为「消耗 320 大卡 · 18 分钟」。**消耗是手填字段（ADR 0029），没填写「消耗 —」**，不拿 0 占位——0 会污染「今日消耗」的心智模型。
- 首页卡不再显示总容量；详情页／汇总页／日志列表的成绩位仍按 ADR 0023／0025，不受影响。
- 该卡片的日期仍是「10月11日」；精确到分只落在日志列表、详情页与汇总页（2026-10-19 同批）。
