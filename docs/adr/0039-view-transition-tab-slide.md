# 切页转场：用整页快照做「旧页左出、新页右入」的连续推拉

Status: accepted · 2026-10-21

起因：主人对 0.17.x–0.18.x 的切页动效连提两轮意见——先是「位移太快」，再是「要连续性的位移，旧页面往左移，新页面往右移」。而此前实现（[ADR 0037](./0037-tab-switch-transition.md)）只有一个方向：**新页入场**；旧页在切换瞬间就消失了，所以左边永远是空白，观感是「一页从右边挤进来」，不是翻页。

结构上的限制要说清：导航改成 `switchTab` 保活之后（[ADR 0038](./0038-tabbar-switchtab-keepalive.md)），页面实例还在，但**框架只让一页在文档里**——非激活页被 KeepAlive 移出文档。所以「两页同时可见、一个滑出一个滑入」在当前形态下靠 DOM 做不到。

## Considered Options

- **加大单页入场的位移（回到 18vw）**：否——那正是「切页看着像白屏」的成因（内容被推出视口、又叠了半透明），主人已经否过。
- **手动克隆旧页 DOM 做滑出层**：否——要处理 fixed 元素、滚动位置、canvas 图表与图片，克隆出来和原页面很难完全一致，还多一份 200ms 的重渲染开销。
- **把四个页面塞进一个壳页、自己管 display**：否——那是 ADR 0038 里否掉的「壳页」方案，等于重写导航层与所有页面生命周期。
- **View Transitions API 做整页快照转场（选定）**：`startViewTransition` 会在切换前后各拍一张整页快照，两张快照可以并排滑动——旧页左出、新页右入，天然连续，且不需要两页真的共存。

## Consequences

- **实现在 `utils/nav.ts` 的 `startSlide(dir, navigate, waitSelector)`**：设根元素 `data-tab-slide`（值＝旧页滑出的方向），在 `startViewTransition` 回调里触发 `switchTab`，并等目标页的 `__body` 进文档（**再等一帧**，让新快照拍到的不是白板）。方向由 `FtTabBar` 按 tab 下标差决定：去右边的 tab → 旧页左滑、新页从右进。
- **样式在 `App.vue`**：`::view-transition-old(root)` / `::view-transition-new(root)` 各挂一条关键帧，`±100%` 屏宽、300ms、`$ease-out`。方向语义由 `:root[data-tab-slide='left'|'right']` 区分，**别改反**。
- **等待上限 150ms**：转场期间屏幕上是**冻结的旧页快照**，等太久就从「滑动」变成「卡住」；等不到就让新快照为空那一帧，直接滑过去。另有一条 300ms 的兜底 `navigate()`，保证点击绝不会变成「没反应」。
- **单页入场动效退役**：有 View Transition 时 `playTabEnter` 直接 return（两套会变成二次位移）；不支持的环境（老 WebView）仍走旧的 8vw 微移，所以 `enterDir` / `enterSeq` 那条链路保留。
- **指示条不再自己播动画**：它跟着整页快照一起动，转场结束时已经在对的位置。
- **已知的观感代价**：底栏是整页快照的一部分，**会跟着一起滑**。若将来要「底栏钉住、只有内容翻页」，得给底栏单独 `view-transition-name`，但两页各有一份底栏、命名必须唯一，得先解决冲突。
- ⚠️ **本地 headless 验不了这个功能**：页面不可见时浏览器会跳过 View Transition（`data-tab-slide` 都不会生效、动画列表为空）。2026-10-21 这次就是靠真机截图才发现本地「验不出来」——**涉及转场的改动只能真机看**，别再拿 headless 的结果当结论。

> 关联：ADR 0037（方向感知横移）、ADR 0038（保活导航）
