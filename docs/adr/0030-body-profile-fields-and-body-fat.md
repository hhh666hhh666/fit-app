# 身体档案的档案字段与体脂率

Status: accepted

需求：身体档案补上年龄、性别、身高等字段（算每日消耗要用），另外体脂率也要能记——「记录体重时加一项体脂率，仅用于记录」。现状 `user` 表只有账号密码，`body_record` 只有体重与四围，没有任何 profile 概念；因此「算消耗」缺输入，体脂率也无处可放。

## Considered Options

- **把字段扩到 `user` 表**：否——`user` 是认证表，塞业务字段会让认证模块被业务污染（[ADR 0003](./0003-register-login-auth.md) 的范围是注册登录）。
- **字段塞进 `body_record`**：否——性别身高是不变值，随每次测量重复存；而且「改档案」得先造一条体重记录，与「一条记录＝一次测定」（[ADR 0017](./0017-body-record-model-and-crud.md)）直接打架。
- **年龄直接存一个数字**：否——明年打开还是 30 岁，而这个数**直接进基础代谢**，会把消耗悄悄算高。存**出生日期**，年龄每次现算。
- **「我的」页新开一个「个人档案」独立页**：否——为四个字段的表单开一条新路由；而且身高性别只在算消耗时用，消耗与体重应当同屏。
- **塞进现有「设置」页**（那里在管图片质量与饮食目标）：否——设置页会从「图片与饮食目标」变成杂物间。
- **体脂率存进档案表当一个「当前值」**：否——改一次就丢掉历史，而体脂本来就是看变化的东西。
- **体脂率单独建一张记录表**：否——「同一时刻量了体重和体脂」会变成两条记录，时间线还要合并，纯增复杂度。
- **体脂并入体重图做第二条线（双 y 轴）**：否——72.5 kg 与 18.4% 量纲完全不同，共用一根轴会读出假相关；做双轴等于给自绘 canvas 加一层坐标系统。
- **新建 `user_profile` 一行一用户 ＋ 体脂率作为 `body_record` 的一列 ＋ 体重卡标题切换序列**（选定）。

## Consequences

- 新表 `user_profile`（迁移 V28，一个用户一行）：**性别／出生日期／身高／生活活动档**。缺行＝未填档案。**体重不进这张表**，仍取 `body_record` 的最新一条——体重是会变的东西，且已经有自己的测定模型。
- 表单落点在 `pages/body/index.vue` **顶部加一张「档案」卡**（四项 ＋ 一行「每日消耗 2400 大卡」 ＋ 「怎么算的」入口），点卡开弹层编辑。**不新开路由**：主人已确认复用「我的 → 身体档案」这个现有入口；顺带把该入口右侧写死的「—」改成最新体重（走 `formatWeight`，跟随斤/千克偏好）。
- 档案与消耗的联动、缺字段的降级都在 [ADR 0029](./0029-daily-energy-and-calorie-gap.md)，本卡只管字段与模型。
- 体脂率作为 `body_record` 的**一列**（迁移 V29）：范围 3.0–75.0，**1 位小数**（体脂秤给的就是 1 位，留 2 位是假精度），可不填。录入弹层里放在**体重那一行下面**（同属体成分），与体重、围度一样预填上次值并标「上次 ×月×日」。
- 体脂率**只记录、不参与任何计算**——不进基础代谢、不进容量/PR、不进缺口。「只填了体脂、没量体重和围度」的记录**可以存**：现有「体重与四围至少一项」的校验扩成「体重、四围、体脂至少一项」。
- 展示：当前卡加一格体脂、记录列表加一列。「体重趋势」卡标题改成「**体重 / 体脂**」，**点击切换**同一张图的序列——不新开图、不做双线。同一时刻只画一条线，因此不需要双轴。
- 顺手修掉的精度问题：图表的**准星气泡**按当前单位精度显示（斤 1 位／千克 2 位），**y 轴刻度保持取整**。两者口径不同是刻意的——刻度是视觉参考、取整更干净，气泡是读数、必须与人眼看到的别处一致（[ADR 0019](./0019-body-weight-unit-and-exercise-batch-delete.md)）。
- 实现时要跟着改：`docs/design/数据模型.md`（`user_profile`、`body_record.body_fat`）、`docs/design/API.md`（档案读写、体脂字段）、`docs/design/前端.md`（档案卡、图表切换）。
