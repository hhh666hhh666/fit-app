# 训练容量的口径与展示

Status: accepted

`workout.total_volume`（Σ 重量×次数）自上线起就出现在六处界面上，但**口径与展示规则从没拍过**：有氧动作走同一套「重量 × 次数」录入、被一并计入；跨动作相加出来的数值被当「成绩」摆在各处；同一个数字背着「总容量」与「总负荷容量」两套名字、两套单位（kg 与 t）。本卡把口径与展示规则定下来。

## Considered Options

- **保持现状（有氧一并计入、各页直接摆数字）**：否——纯有氧的那天显示「总容量 0 kg」像故障；重量栏随手填个数就污染全局；跨动作相加的数值没有生理含义，摆在页面上只会误导。
- **砍掉容量，只留组数与时长**：否——容量是力量训练里最通行的「渐进超负荷」代理指标，同一计划纵向对比时是有效信息；砍掉等于扔掉唯一能横向汇总的量。
- **只在当次训练里保留，跨期全部删除**：否——「上月 vs 本月」这类对比正是容量最成立的用法；删掉只剩当场反馈，信息量弱于组数与 PR。
- **容量只累计力量动作；每次展示都必须带对比基准（同计划上次／上一周期），无基准不给差值；标签按实际口径命名**（选定）

## Consequences

- **有氧动作不参与容量**：判定动作是否计入要看肌群码（`exercise.category = cardio` 排除，自定义动作标了「有氧」同样排除），所以服务端算容量与 PR 时要能拿到每个动作条目的肌群码——不能只看 `workout_set`。
- 有氧动作的容量位显示「—」而不是 `0`；训练汇总页与详情页的三格指标在**纯有氧场次**下第三格为空。
- 历史 `total_volume` 是按旧口径累加的，与新口径不一致 → 需要一次性重算（按 `workout_block` join `exercise.category` 反算），见 [容量与 PR 口径改造待办](../todo/archive/2026-10-16-TODO-容量与PR口径改造.md)。
- **标签必须与数据口径一致**：「我的」页那格字面是「累计训练／总负荷容量」，实际只统计最近 200 次（`listWorkouts(200)` 封顶）——要么改成真全量，要么如实写「最近 200 次」，不允许继续用「累计／总」这种字面全量的说法。
- 术语收束：`CONTEXT.md` 收录「总容量」；**「容量」在训练语境下专指本口径**，餐照的存储占用一律写「存储占用」，避免同词两义。
- 前端与数据模型说明需同步（`docs/design/前端.md`、`docs/design/数据模型.md`），并核对 `docs/requirements/scope.md` 的范围表。

> 关联：PR 判定口径与本次容量口径同源，另立一卡 → [ADR 0024](./0024-pr-definition-heaviest-set.md)。

> ⚠️ **后续（2026-10-16 讨论补定）**：
>
> - **全站容量单位统一 kg**：「我的」页那格取消 `t` 显示，标签统一叫「总容量」（数值本身是 Σ(重量×次数)，量纲上是 kg·次，界面按 kg 表述）。
> - **有氧一并排除出 PR 判定**：不只容量，`muscle = cardio` 的动作不参与 PR——`isPr` 现行规则是「无历史即为 PR」，不排除则第一次练就会被标成 PR。
> - **累计类数字必须走全量聚合**：「我的」页新增一次 `SUM(total_volume)` 的接口，不再用「最近 200 条求和」冒充「累计」。
> - 落地清单与历史数据重算口径见 [容量与 PR 口径改造待办](../todo/archive/2026-10-16-TODO-容量与PR口径改造.md)。
