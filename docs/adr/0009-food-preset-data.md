# 食物库引入系统预置数据，预置只读

Status: accepted

> 本卡**收窄 [ADR 0008](./0008-diet-logging-module.md) 中「食物库完全自建、无预置」的结论**，其余结论不变。

2026-10-12 拍定：食物库从「全自建」扩为**「系统预置 ＋ 用户自建」双来源**。预置数据来自两份数据文件——《中国食物成分表》1677 条（营养完整）＋ 血糖生成指数表 259 条（GI 数据，能挂的并入对应食物、挂不上的补搜公开资料后独立入库、名字加 `*` 标「外部补全」）。预置共约 1800+ 条，**只读**（不可改删，可「复制为自定义」建自己的副本）；引导性动机：全自建意味着冷启动要手敲 1600+ 条，数据本身又是公开标准数据，没有理由让用户重编。

## Considered Options

- **预置可改（仅不可删）**：否——改完无法还原，「默认数据」名存实亡；要微调走「复制为自定义」，改的是副本。
- **给食物表加 `built_in` 显式字段**：否——`user_id` 放宽可空后「空即预置」本身就是标记，动作库（`exercise`）已用同一范式；两个库一种表达，不加冗余列。
- **预置数据走「应用启动时从资源文件导入」**：否——项目已有 V5 预设动作的**迁移脚本**范式；国标数据几乎不再更新，零新机制最优。
- **4+1 缺失的 158 条整体放弃**：否——117 条只缺钠（钠不参与快照与任何统计），16 条缺的项营养学上确凿近零（食用油缺蛋白质、蛋清缺脂肪、蔬果缺脂肪）；只有 25 条（缺碳水等核心项的冷门野菜/蜂产品）外部补搜。因此**钠列放宽可空**（NULL=未测），不扩大 `meal_log` 与记录链路的改动。
- **GI 表孤儿（约 150 条）不导入 / 以「无营养空壳条目」入库**：否——空壳条目搜得到却记不了（四环算不了数）反成困惑；改走「公开资料补全营养 + `*` 入库」，可被正常记录。
- **「确凿补 0」的条目也加 `*`**：否——`*` 语义定为「数据可信度低一档（外部补全/估算）」；确凿 0 与国标同级，不加。
- **系统预置 ＋ 用户自建、预置只读、复制为自定义、补全条目加 `*`（选定）。**

## Consequences

- 迁移 V12：`food.user_id` 放宽可空（NULL=预置）、`sodium` 放宽可空（预置未测）、新增 `category`（国标大类，仅预置使用）；预置数据本体走 V13 数据迁移（搜补完成后生成）。
- 「用户自建 4+1 必填」的输入规矩**不变**（校验在 DTO 层）；导出只导自有、导入查重只看自有（允许与预置同名）；餐次记录可直接引用预置食物（快照照写，四环不受影响）。
- 列表/搜索对「预置＋自有」合并；预置的改/删被服务层以 `FORBIDDEN` 拦截；列表接口新增 **lite 轻量模式 ＋ limit**（预置 1800+ 条不再全量拉取）与新单条查询接口。
- 数据口径：`—`→留空、`Tr`→0；国标重名条目照原名保留；外部补全条目名字加 `*` 后缀（前端注明含义）。
- 与 ADR 0008 的差异：其「冷启动库是空的、建库与记录并行」的代价失效；「拍照识别不做」「图片存 MySQL」等其他结论不受影响。
- 数据明细（GI 挂载映射 86 条、外部补搜清单 169 条、放弃 2 条）随数据批次落盘到工程目录。
