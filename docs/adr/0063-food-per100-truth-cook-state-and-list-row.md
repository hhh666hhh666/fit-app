# 食物以每 100 为唯一准数；加「生重／熟重」；食物列表行改版，点「+」才记录

Status: accepted · 2026-11-23

主人编辑食物时，在「每份」模式下改克重，每份的营养不跟着变，保存后每 100 反而被改乱了：按份录入时页面把输入框里的每份数当成准数，保存时又拿新克重反推每 100。同一批里主人还要求：食物能标生重或熟重、列表每行显示三大营养素、「预设」标签换个不扎眼的区分法、记一餐时按份可以填任意份数。

## 决策

1. **每 100 是唯一的准数**。录入只填每 100，「每 100 / 每份」切换和切换时问份量的弹窗都去掉；填了常用份后，每个营养框旁边实时显示只读的「每份 xx」。包装只印了每份的，用标签识别时系统换算成每 100 并把份量填进常用份；手动录入要自己算好每 100 再填。推翻 scope #52 的「按份录入」。
2. **生重／熟重**：食物多一个可选属性——生重、熟重或不标。预置的由管理员在管理端设，可以取消；自定义的在 App 编辑页设。现有食物一律不标。不标就不显示；标了在名字后面显示小标签，生重浅绿、熟重暖褐。JSON 导入导出带上它；记下的餐次条目不存它。
3. **列表行**（食物库页、记一餐列表；组合编辑不动）：三行——名字和生熟标签 / 「1份（200g）」或「每100g」/ 碳水、蛋白、脂肪带色点；右边是大卡（有常用份按一份，没有按每 100）。比原来整体小一号。
4. **预置与自定义的区分**：预置不标；自定义在缩略图右下角挂一个浅橙铅笔角标，没有图片时显示统一的占位底。「已下架」保留文字标签。详情页写「来源：预置 / 自定义」。界面上「预设」统一叫「预置」。
5. **记一餐列表**：点行右边的「+」弹出份量行（就是原来点食物的效果）；点食物这一行进食物详情页，只看、不记，返回仍在弹层里。临时条目没有详情页，点行和点「+」一样。
6. **份量行**：有常用份的食物可以在「份 / g」之间切换，默认按份、1 份；按份时显示总重量，按 g 时显示合多少份。没有常用份的只有 g。原来的「1份」「×2」两个按钮去掉。已记条目的「修改份量」用同一套。

## Considered Options

**改克重时谁不动**

- **每份数不动、每 100 跟着变**（原来的做法）：否。每 100 是食物的本体，改一个份量就把它改掉，正是这次的缺陷。
- **每 100 不动、每份跟着变；仍可按每份录入，份量第一次填上时再换算**：否。规则有两条，填错份量再改时还会把录入的每份数按比例改掉，主人要的是只有一条规则。
- **只录每 100，每份只读**（选定）。

**预置与自定义怎么区分**

- **继续给预置贴标签**：否。一千多条预置几乎每行都挂着它，显得杂。
- **只给自定义贴文字标签**：否。和生熟标签挤在一起、长得一样。
- **列表里完全不区分**：否。同名的预置和自定义分不清。
- **缩略图角标**（选定）。

**点食物行做什么**

- **点行直接按默认份量记一条**：否。主人要点「+」才记录。
- **点「+」弹份量行、点行看详情**（选定）。

## Consequences

- 迁移 V49 给食物加生熟列；标签识别草稿回填常用份；管理端编辑页、导入导出都要认这个字段。
- 食物编辑页的按份换算、`per100Origin` 这些都删掉，换成只读的每份显示。
- 术语表改「食物」，加「生重／熟重」，「预设」「自建」统一为「预置」「自定义」。
