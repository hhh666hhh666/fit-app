# 餐照：一餐可以有多张，按 id 取图

Status: accepted · 2026-10-31

主人要一餐能记多张照片。这也顺带消掉了回收站恢复餐照时「同一餐已有新照片」的冲突。取代 [ADR 0013](./0013-photo-storage-and-quota.md) 与 [ADR 0014](./0014-photo-viewer-and-album.md) 里「每餐一张、重拍即替换」的部分。

## Considered Options

- **保持一餐一张，恢复时两张互换**：否——主人要多张，互换只解决冲突，解决不了记录需求。
- **设每餐张数上限**：否——恢复时又会碰上「这一餐满了」，只受总配额限制就没有这个冲突。
- **保留「更换」**：否——换图等于删旧加新，旧图进回收站，不需要第二条路径。
- **保留 `/photos/{date}/{meal}` 接口，返回该餐第一张**：否——一餐多张后它指不准某一张，留着只会让 agent 和旧客户端拿错图。
- **一餐不设张数上限，取图、删图都按 id，新图的文件名带随机串**（选定）。

## Consequences

- 去掉 `(user_id, log_date, meal)` 唯一键。上传的幂等改靠本次上传生成的路径：重试时查到同路径的行就不再插入。
- 老照片的路径是 `{userId}/{logDate}/{meal}`，继续有效；新照片是 `{userId}/{logDate}/{meal}-{随机串}`。不复用路径，新上传才不会覆盖回收站里还留着的旧文件。
- 选图一次最多 9 张；餐次弹层改成一排缩略图 ＋「添加」，点开全屏可左右翻。
- 外部 agent 的取图地址随之改成 `/api/agent/photos/{id}`，从 `photos[].url` 读地址的 agent 不用改，写死旧路径的要改（[ADR 0043](./0043-external-agent-read-api.md) 的后续）。旧版 App 在自动更新前取不到餐照。
- 回滚到旧版本时，一餐多张的数据会让旧代码的单行查询报错，所以这次发布后只能往前修。
