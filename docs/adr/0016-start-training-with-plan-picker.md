# 开始训练：改为「先选计划」（周安排降为默认项）

Status: accepted

**取代 [0004](./0004-week-schedule-driven-start.md) 中「按当天自动执行」的那部分**（0004 的其余结论继续有效，见 Consequences）。

点「开始训练」不再按周安排自动匹配当日——**总是先弹计划选择器**：今天的计划置顶并标「今天 · 建议」，其余计划跟在后面，选任一个即进训练会话；底部保留「自由训练」出口；一个计划都没有时给「去新建计划」的出口。周安排不废，但语义从「自动执行」降为「决定谁置顶 ＋ 首页底部小字提示什么」；选择器里选了跟周安排不一样的计划**不回写周安排**。计划内容（新建／改名／改动作编排／删除）的唯一入口仍是「我的 → 训练计划」——选择器只能选、不能改。

## Considered Options

- **保留直进，只在「休息／未安排」弹层里把「调整训练安排」换成「选择训练计划」**：否——今天明明是休息日却弹「选择训练计划」，语义矛盾；且「今天有安排但临时想换个计划练」（实际很常见）仍要绕到「我的 → 训练安排」改今天，等于没解决痛点。
- **今天有安排直进，首页另开一个「选计划练」入口**：否——正是 0004 撤掉的双入口，两个入口会让人反复纠结该走哪个。
- **做成独立页面而非首页弹层**：否——多一次跳转、多一个页面要维护；自用的计划数量一屏放得下，弹层足够。
- **选了别的计划后顺手改写周安排**：否——那等于在选择器里改周安排，违反「训练计划与周安排的修改入口唯一在『我的』页」；且会让「置顶项」的语义自相矛盾（改完就没有「今天的计划」了）。
- **总是先弹选择器、今天的计划置顶**（选定）。

## Consequences

- 0004 里「每次开始弹『选择计划』层：否」这条被推翻。原判据是「把这个决定留给用户每天做一次，违背 30 秒记录动线」；实际用下来真正的痛点是**临时换计划要绕远**，而多一次点按（点一下置顶项）的代价很小。0004 其余部分继续有效：周安排的数据结构、一格三态、「休息」语义、计划名一律用户自定义、撤除「按计划开始」双入口。
- 首页底部小字「今天 · ＜计划名＞」保留，作用是**在选择器里呼应置顶项**，不再是「点下去就练它」的承诺。
- 「我的 → 训练安排」成为周安排的**唯一**入口——首页弹层不再有「调整训练安排」。
- 「我的 → 训练计划 → 点卡直接开练」保留：它解决的是「翻计划时顺手开练」，与选择器（练前选）主场景不同，不算双入口回归。
