# 预置动作接入开源动作数据集：资料进库，动图放上传目录

Status: accepted · 2026-11-11

主人要把开源数据集 [hasaneyldrm/exercises-dataset](https://github.com/hasaneyldrm/exercises-dataset) 的**全部动作**（1324 个）收进预置动作库，**动图一起用上**。数据集给每个动作配了英文名、部位、器械、目标肌、辅助肌群、10 种语言的分步要领、一张 180×180 缩略图和一段 180×180 动图。

许可分两半：名字、分类和要领文字是 MIT，可以随便用；**缩略图和动图版权归 Gym visual**，数据集是拿书面许可转发的，并写明「克隆不等于授权，要用请自己向 Gym visual 取得许可」。2026-11-10 已向主人说明这一点，主人仍决定用上动图，这是主人的决定。下面的做法只是把影响面压到最小，不等于取得了授权。

## 决策

1. **数据进库，走管理端导入**（守 [ADR 0049](./0049-preset-data-source-of-truth-is-database.md)）。V42 只给 `exercise` 加列：数据集编号、英文名、器械、目标肌、辅助肌群、要领、动图键，全部可空。数据由 `scripts/exercise-dataset/build.py` 生成导入文件，在管理端「预置动作 → 导入」先预检再整批写入。
2. **中文名由 AI 逐条拟定**，存在 `scripts/exercise-dataset/names-zh.tsv`（编号→中文名，可以人工改了重新生成）；部位按固定对照表落进七个肌群（颈部两个归肩）；器械、目标肌和辅助肌群译成中文；要领取数据集自带的中文版，去掉每条结尾那句千篇一律的「重复所需次数」。
3. **和老预置合并，不重复建**：导入时先按 `id`、再按数据集编号认已有的那一条；都没有时，**同名且还没有编号**的老预置被「认领」——只补资料和编号，名字和肌群不动（老预置被人练过，改肌群会让历史统计变口径）。原有 60 个里有 55 个就这样接上了动图；站姿杠铃推举、面拉、侧平板支撑、划船机在数据集里找不到对应，保持原样。记录口径、上下架、排序一律不动，新增的排到最后。
4. **动图和缩略图放上传目录的 `exercise-media/`**，由 `scripts/exercise-dataset/sync-media.sh` 放进去（线上经 SSH rsync），应用只读不写。**不进 git 仓库**（仓库是公开的），**接口要登录才给**（`GET /api/exercises/{id}/media`），App 上带「动图 © Gym visual」署名，尺寸保持 180×180 不放大重存。
5. **App 加动作详情页**：动作库点动作进入，显示动图、英文名、练到哪里（肌群、器械、目标肌、辅助肌群）和动作要领。自定义动作没有这些资料，只显示名字和肌群。PR、趋势、历史这些复盘内容不在这一步，见 [动作详情页待办](../todo/2026-11-09-TODO-动作详情页.md)。

## Considered Options

**动图怎么办**

- **只用文字，不用动图**：否——主人明确要动图。
- **前端直接链 GitHub 上的原图**：否——等于把版权图片挂在公开地址上取用；而且服务器和手机在国内，GitHub 原图地址时通时断。
- **存进数据库**：否——[ADR 0026](./0026-photo-storage-and-backup.md) 刚把图片从库里搬出去，126 MB 动图塞回去会让每天的库备份重新变胖。
- **上传目录 ＋ 登录后才能取**（选定）：和餐照同一套挂载、备份（硬链接快照，文件不变就不额外占空间）；不公开、不进仓库。

**数据怎么进库**

- **写一个 Flyway 迁移灌 1324 行**：否——违反 ADR 0049，迁移按名字改预置会覆盖线上在管理端做过的修改。
- **应用启动时从资源文件同步**：否——ADR 0049 已否过，会冲掉在线修改。
- **管理端导入预置动作，先预检再写**（选定）：和预置食物的导入同一套路；导出格式就是导入格式，以后批量订正也走它。

**动作库一千多条之后**

- App 动作库列表照旧一次取全，前端每次铺 60 行、滑到底再加，搜索同时匹配中英文名；列表接口不读要领那一列。
- 「我的」页的动作数改走计数接口 `GET /api/exercises/count`，不为一个数字拉全量列表；列表约 180 KB，超过冷启动快照的单条上限，本来也落不了盘，快照白名单换成计数接口（[ADR 0036](./0036-cold-start-cache-persistence.md)）。
- 管理端表格前端分页（每页 100 行），「被引用」改为一次查出所有被引用的动作，不再逐行查。

## Consequences

- 预置动作从 60 个变成约 1330 个。动作库「全部」一栏变长，按肌群筛和搜索是主要用法。
- 中文名是 AI 拟的，要领是数据集自带的机器翻译，读起来有翻译腔；发现不对就改 `names-zh.tsv` 重新生成再导入（按编号更新，不会重复建），或在管理端单条改名。管理端暂时只能改名字、肌群、口径和排序，改不了要领。
- 动图没同步到服务器时，详情页照常显示文字，动图位置不出现（接口按文件在不在判断）。
- 数据集以后更新：`fetch.sh --update` → `build.py` → 导入（按编号更新）→ `sync-media.sh`。
- 版权风险由主人承担：动图仍是 Gym visual 的，日后要给别人用，先取得授权，或者把动图撤掉（删掉 `exercise-media/` 目录即可，文字不受影响）。
