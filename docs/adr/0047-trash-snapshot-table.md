# 回收站：独立表存 JSON 快照，原表照常物理删除

Status: accepted · 2026-10-31

之前的删除基本都不可恢复，手滑只能翻备份。现在一次训练、日记、餐照、日记图片、身体档案、计划、自定义动作、自建食物和「开新的」丢掉的训练，都先进回收站，保留 30 天。在回收站里等同已删除，所有统计和接口都看不到，恢复后原样回来。

## Considered Options

- **各表加 `deleted_at` 标记**：否——`@TableLogic` 管不到手写 SQL，粗略统计有 40 多处要逐条加条件，漏一处就会让已删的训练混进 PR 或统计，而且不报错；食物同名、餐照这类唯一约束也要改造。
- **按一次删除操作打包成一组**：否——列表和恢复逻辑都更复杂；多选删 N 条就是 N 条独立条目。
- **做回收站详情页**：否——每种类型都要一套渲染；想看完整内容就先恢复。
- **保留期内恢复丢掉的训练时，成一条训练记录**：否——一组没勾的恢复不了，[ADR 0011](./0011-session-early-finish-and-leave-guard.md) 也不允许空训练入库。所以恢复成进行中的训练会话。
- **「开新的」断网时拦住**：否——自由训练和有缓存的计划本来不用联网，不该因此开不了新训练。改为本机暂存，有网时补传。
- **独立回收站表存快照，恢复时按原 id 写回**（选定）。

## Consequences

- 现有查询都不用动。恢复按原 id 写回，记录引用和弱引用自然恢复。
- 快照要能跨迁移恢复：反序列化时忽略未知字段，新增列用默认值。每类数据各有一份写回逻辑（`TrashHandler`）。
- PR 标记不回改：「当时是否破纪录」是历史事实，恢复后可能同时有两次带标记，「当前最佳」仍是现算的。
- 恢复一定成功：食物和计划重名自动加「（恢复）」后缀；周安排只填回仍空着的格子。例外是丢掉的训练：已有进行中的训练时不恢复，提示先结束，不把正在练的换走。
- 自定义动作不走快照：PR 列表 INNER JOIN 动作表，物理删掉 PR 就没了。所以它继续只是下架，到期或彻底删除时只摘掉恢复入口，行永远留着。
- 照片文件留在原处，到期或彻底删除才删。回收站里的照片继续占 20 GB 配额，删图后空间不会马上释放。
- 只有「开新的」丢掉的训练进回收站；一组没勾就结束、提前结束时未完成的组不进。餐次条目和食物组合继续物理删除。
- 每天 04:10 清理到期条目，排在备份之后。彻底删除不影响已经打进备份快照的数据。
