# 有氧动作的专属记录口径（爬楼按层数）

Status: accepted

[ADR 0023](./0023-volume-metric-scope-and-display.md) 把有氧动作整体排除出容量与 PR 之后，有氧变成「能记录、但不参与任何统计」——缺的正是它自己的指标。而在实际用法里，爬楼要看的数字是**层数**（这次爬了多少层），「重量 × 次数」对爬楼没有意义。本卡定下第一个有氧专属口径。

## Considered Options

- **复用 `reps`（次数）栏，按动作类型把标签改成「层数」**：否——库里 `reps` 的语义被泛化，导出与后来的统计分不清「次数」与「层数」，且这是不可逆的脏数据。
- **只做展示（层数仍填在次数栏，页面另算一个「本场总层数」）**：否——与上一条同样的歧义，只是把问题往后拖。
- **整场只填一个「总层数」**：否——与「组次」模型冲突（这个数塞进哪一组？），详情页与编辑页得为有氧单开一套录入与展示，反而更重。
- **`exercise.metric` ＋ `workout_set.floors`：口径声明在动作上、层数落在自己的列；有氧块的组行只留一个「层数」栏**（选定）

## Consequences

- **口径声明在动作上**（`exercise.metric`：默认 `weight_reps`，爬楼为 `floors`），**数据落在组次上**（`workout_set.floors`）。以后跑步要记公里、跳绳要记个数，各加一列 ＋ 各自的口径值即可，不必再动这套结构。
- `metric = floors` 的组，`weight`／`reps` 存**占位值 0／1**，且由**服务端强制归一**（不信客户端）：宁可留两列占位，也不让同一个数在两套语义里混用——这是被否掉的「复用次数栏」方案要付的代价，本卡选择把它限制在数据层的两个无意义字段上。
- **历史爬楼的层数无法反推**（当时口径未定，可能填在重量或次数栏），一律留 NULL、页面按「—」显示；容量与 PR 早在 V23 就把有氧排除，历史数字不受影响。
- 「上次数据」提示对 floors 口径显示「上次 20 层」，而不是「0 kg × 1」。
- 三个页面（会话页、汇总页、详情页）的「成绩位」统一由 `frontend/src/utils/metric.ts` 判定：有力量动作 → 容量；只有层数 → 总层数；都没有 → 「—」。`metric = floors` 的动作既不参与容量也不参与 PR（沿用 ADR 0023／0024）。
- 详情页编辑态对 floors 组只给一个「层数」输入框，组用时（ADR 0022）照旧；校验也只看层数。
- 受影响文档：`docs/design/数据模型.md`、`docs/design/前端.md`、`CONTEXT.md`（术语「层数」「记录口径」）、`docs/requirements/scope.md`。
