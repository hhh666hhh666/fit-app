# 食物搜索：按字顺序也能命中、按匹配度分档、按记录次数排「常用」；食物加别名

Status: accepted · 2026-11-15

食物库页、记一餐的选食物弹层、组合编辑三处共用一套列表与搜索。原来的排序是「收藏 → 浏览次数 → 名称」，搜索要求关键词连着出现在名字里。这有几个问题：

- 浏览次数只在打开详情页时加一，记一餐、加组合都不加，天天吃的东西排不上去。
- 新建的自定义食物浏览次数是 0，会和一千多条没用过的预置混在一起，常常排在后面。
- 搜「猪肠」找不到「猪大肠」，搜「肥肠」更找不到。
- 搜「米饭」时，叫「米饭」的那一条不一定排在「米饭炒蛋」前面。

## 决策

1. **筛选**：关键词里的字按顺序出现在名字或别名里就算命中，中间可以隔别的字，所以「猪肠」能命中「猪大肠」。只输一个字时和原来一样。
2. **排序**：先按匹配程度分四档，名字、名字方括号里的叫法、每个别名都拿来比，取最好的一档：完全一样 ＞ 开头一样 ＞ 连着包含 ＞ 只是按字顺序对得上。同一档里依次比较：收藏 → **这个用户近 30 天（含今天）记过几次** → 自建排在预置前面 → 名称、id。
3. **浏览次数不再参与排序**，字段和「详情页加一」照旧保留。
4. **别名**：食物多一个「别名」字段，一条最多 10 个，每个不超过 16 字。谁能改这条食物的名字，谁就能改它的别名：自建食物由用户自己改，预置食物由管理员在管理端改。个人不能给预置食物加只有自己看得到的别名。别名不参与同名检查。
5. **预置名字里方括号的叫法不搬**：《中国食物成分表》有 393 条把别名写在名字里（如「番茄［西红柿］」），这些名字保持原样，新叫法只存进别名字段。排序分档时，方括号里的叫法和别名字段同样对待。
6. **第一批别名**由 AI 起草，只收日常叫法和成分表名字差得远的常见食物（约 150 条，放在 `scripts/preset-data/aliases-zh.tsv`），主人看过后按 ADR 0049 走管理端导入：导出 → `merge-aliases.py` 合并 → 预检 → 导入。

## Considered Options

**「常用」看什么**

- **继续看浏览次数，记一餐时也加一**：否。预置食物的浏览次数是所有用户共用一份，人一多就互相干扰；而饮食记录本来就是按用户分开的。
- **看全部历史的记录次数**：否。饮食习惯变了以后，以前常吃的东西会一直压在前面。
- **看近 30 天的记录次数**（选定）。

**自定义食物放在哪一层**

- **自建整体排最前**：否。JSON 导入或「复制为自定义」可能留下很多不常吃的自建食物，它们会压住每天都吃的预置食物。
- **放在记录次数之后**（选定）。大部分预置食物从来没记过，新建的自定义食物仍然排在它们前面，已经接近「自定义靠前」的效果。

**名字匹配是否一定排在别名匹配前面**

- **是**：否。搜「肥肠」就是想找猪大肠，不该被名字里带「肠」的条目挡在后面。
- **名字和别名同等对待，取最好的一档**（选定）。

**名字方括号里的别名**

- **搬进别名字段，名字只留原名**：否。这些名字是成分表原文，历史记录里也存着名字的快照；393 个名字的分隔符有顿号也有逗号，中间还夹着圆括号，逐条拆的风险比收益大。
- **不动名字，排序时把方括号里的叫法也算作别名**（选定）。代价是别名分在两处，术语表的「别名」条目写明了这一点。

**模糊匹配做到什么程度**

- **拼音或首字母搜索**：暂不做。需要拼音库、加一列拼音、给已有数据补拼音，主人没有提这个需求。
- **字可以不按顺序**：否。无关结果会明显变多。
- **字按顺序出现**（选定）。说法完全不同的（如「肥肠」和「猪大肠」）靠别名解决。

## Consequences

- 排序写在 `FoodMapper.search` 的注解 SQL 里，用关联子查询数 `meal_log`；wrapper 只放筛选条件，不能放 `orderBy`。食物计数接口用同一个筛选条件，否则食物库页滚动到底的判断会出错。
- LIKE 的转义符用 `!`，不用反斜杠（MySQL 开 `NO_BACKSLASH_ESCAPES` 时反斜杠不再是转义符）。关键词一律通过参数绑定，不拼进 SQL。
- ⚠️ 别名列带 TypeHandler（库里用 `|` 连接，Java 里是列表）。MyBatis-Plus 的 lambda 条件（`like(Food::getAliases, ..)`）会用它转换参数，传字符串直接报错，所以查别名一律用 `apply` 绑定字符串；`set(Food::getAliases, ..)` 不走 TypeHandler，要直接给 `肥肠|大肠头` 这种存库写法。
- 排序分档时，名字里的 `［` `］` `、` `，` 都会换成分隔符，所以圆括号里的逗号也会被切开（如「猪肉（后臀尖，杜长大猪）」里的「杜长大猪」也算「开头一样」）。这只影响排序，不影响搜不搜得到。
- 搜索结果里，名字对不上、靠别名命中的行，会小字标出「别名：…」；详情页显示「也叫：…」。
- 预置食物的收藏仍然是全局共享的，改成按用户记已在 [管理端后续](../todo/2026-11-04-TODO-管理端后续.md) 里。
