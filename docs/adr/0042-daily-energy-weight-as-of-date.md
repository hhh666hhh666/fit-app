# 每日总消耗按当时体重计算

Status: accepted · 2026-10-30

设计外部 agent 接口时发现：每日总消耗算任何一天都取**全局最新**一条体重，结果又不落库。所以在饮食页翻历史某天，看到的消耗和缺口是按今天的体重算的，甚至可能用上那天之后才量的体重；每记一次新体重，过去每一天的数字都会跟着变。[ADR 0029](./0029-daily-energy-and-calorie-gap.md) 写「最新体重」时考虑的是当天的即时反馈，没有讨论翻看历史。本卡收窄 0029：基础代谢改用**那天结束前最后一次测得的体重**。

## Considered Options

- **保持全局最新体重，接口不提供历史消耗**：否——App 翻历史时的错数还在，而且主人本来就认为历史是按当时体重算的。
- **保持全局最新体重，接口照样提供历史消耗**：否——体重变化越大，算出来的历史序列错得越多，还看不出错。
- **把每天的消耗结果落库**：否——要加表，还要处理改体重、改档案后的回算；现算只需换一个取值条件。
- **那天之前没有体重时，用之后最近的一条兜底**：否——[ADR 0029](./0029-daily-energy-and-calorie-gap.md) 已定缺项不算、不产出假精度。
- **同一天取最小值（与身体档案图表一致）**：否——图表取最小值是为了看趋势（[ADR 0017](./0017-body-record-model-and-crud.md)）；这里沿用「最后一条」的取法，算今天时与现状一致。
- **取那天结束前最后一条有体重的记录，之前没有就不算**（选定）。

## Consequences

- 算今天时结果基本不变；只有测定时刻填在未来的记录不再计入。
- 饮食页翻历史时数字会变成按当时体重算；早于第一条体重的日子显示缺体重。
- 身高、性别、生活活动量没有历史，仍用当前值，历史消耗因此只是**近似值**；年龄与训练消耗本来就按那一天算。
- 改、删一条历史体重，会影响它之后直到下一条体重之间每一天的消耗。
- App 仍不做缺口的历史曲线与统计（[ADR 0029](./0029-daily-energy-and-calorie-gap.md)）；只有外部 agent 接口会批量提供历史消耗，口径见 [ADR 0043](./0043-external-agent-read-api.md)。
- 消耗口径仍只有 `EnergyService` 一处实现。
