# 日记：Markdown 原文存储、图片插在正文、记录引用实时读取

Status: accepted · 2026-10-30

主人要一个支持 Markdown 的日记：内容不限，一天可写多篇，第一版就能插图，还能在正文里引用某次训练或饮食。它把范围从「训练、饮食、身体」放宽到一段自由文字，也是第一个让图片脱离「每餐一张」的功能。本卡定下正文、图片和引用三者的形状。

## Considered Options

- **只让一次训练的备注支持 Markdown**：否——写不了与某次训练无关的内容。
- **一天一篇，再写就是续写**：否——主人要一天多篇，所以一篇有自己的时刻和可选标题。
- **正文第一行的 Markdown 标题兼任标题**：否——主人要单独的可选标题，列表优先显示它。
- **所见即所得编辑器**：否——要引入编辑器依赖，主包更重；写原文加快捷按钮和预览已经够用。
- **引入完整的 Markdown 渲染库**：否——主包变重，还要防内嵌 HTML 的注入；现有解析器输出结构化块、不走 `v-html`，扩展常用语法就够。
- **按 Markdown 标准，单个回车不换行**：否——日记里按回车就该换行；接口文档页仍按原口径解析。
- **图片统一排在正文后面**：否——不能图文穿插，主人要的是 Markdown 里的图。
- **用餐照的路径键和表存日记图**：否——餐照是「每餐一张、同路径覆盖」，日记图数量不定，要有自己的表和随机文件名。
- **靠扫描正文判断图片是否还被引用**：否——每次保存和删除都要扫全部正文；单独一张引用表，保存时同步。
- **保存时立即清理正文里去掉的图**：否——会误删另一台设备草稿还在用的图。
- **日记图单独设配额、或不进相册**：否——多一个要管的数字；不进相册时，配额满了清不掉日记图，违背 [ADR 0013](./0013-photo-storage-and-quota.md) 不把主人锁在门外的原则。
- **记录引用存快照**：否——数据要多存一份，记录改错后日记里仍是错的。
- **引用细到单条餐次条目**：否——条目没有稳定身份，改一餐就可能失效。一餐按「日期 ＋ 餐次」定位。
- **引用单独存表或存字段**：否——引用的位置就在正文里，存在正文语法中，导入导出都不用多管一份。
- **训练详情和饮食页反向显示引用它的日记**：否——要反查正文，也模糊了日记和备注的边界。
- **服务端加密或 App 锁**：否——主人选择和现有健康数据同一等级；代价见下。
- **进外部 agent 接口**：否——通用日记会写私事，agent 可能把内容发给模型服务，发出去就收不回来。
- **App 内点链接直接打开或交给系统浏览器**：否——壳把所有跳转留在 App 内，打开外链会顶掉当前页；交给系统浏览器要发新 APK。第一版弹「复制链接」。

## Consequences

**正文**

- 存 Markdown 原文。解析器 `utils/markdown-lite.ts` 增加富文本选项，接口文档页不受影响。
- 不支持的语法（表格、嵌套列表、内嵌 HTML）按原文显示；只接受 `http`、`https`、`mailto` 链接。
- 图片是单独一行的 `![图片](diary-photo:<id>)`，记录引用是单独一行的 `[说明](fit-ref:<键>)`，键为 `workout/<id>`、`meal/<日期>/<餐次>`、`day/<日期>`。⚠️ 这两种语法写进了主人的正文，是长期格式，改它们要迁移数据。
- 单篇上限标题 50 字、正文 2 万字，时刻不能选未来。

**保存**

- 本机实时存草稿，点「保存」才上传；每个编辑对象一份草稿（新写一篇共用一份）。多端同改时后保存的覆盖先保存的，和其他数据一样不做版本号（[ADR 0035](./0035-client-cache-and-invalidation.md)）。

**图片**

- 插图时立刻上传，所以断网插不了图，但文字还能写。图片落在现有上传目录下，每日快照和 OSS 备份自动覆盖（[ADR 0026](./0026-photo-storage-and-backup.md)）。
- 共用餐照的 20 GB 配额，占用卡显示合计；相册分「餐照」「日记」两栏，日记栏按上传日期分组。
- 删除顺序沿用「先删行、后删文件」：最坏只留孤儿文件。
- 在相册删掉的图，正文显示「图片已删除」。
- 没有任何日记引用的图，满 30 天由每日任务清理，清理前仍占配额。「满 30 天」从最后一次失去引用算起，所以记了失去引用的时刻，而不是看上传时间。
- 删除日记时，只属于它的图立即清理；另一台设备草稿里还在用的图此时也会失效，接受。

**记录引用**

- 卡片每次打开实时读取，记录删了显示「这条记录已删除」，删除记录时不拦也不提醒。
- 饮食页新增按日期打开，供卡片跳转。

**隐私**

- 日记明文进库和备份，服务器和 OSS 上的备份都能读到内容。将来要加密时，已有正文要一起迁移。
