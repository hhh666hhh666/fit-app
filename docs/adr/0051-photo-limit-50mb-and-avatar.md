# 单张图片上限提到 50MB；头像保留原图，历史头像切回时重新裁剪

Status: accepted · 2026-11-06

单张图片原来最多 10MB。有损的三档会先压到长边 1600px，碰不到这条线，但「无损」档直传原图，高像素手机拍的原图会被拒。这次把餐照、日记图片和头像的上限提到 **50MB**。同时新增**头像**：在「我的」页页头代替名字首字母，用过的都留在**历史头像**里。

## Considered Options

**上限提到多少**

- **20MB 或 30MB**：否——主人选了 50MB，高像素模式的原图也能放得下。
- **50MB，标签识别的 5MB 不变**（选定）。识别那道限制来自识别接口：图片要转成 base64，体积会再涨三成多，和上传上限不是一回事。

**50MB 怎么扛住内存**

线上后端的堆只有 256MB（[内存策略](../operations/内存策略.md)）。后端原来会把整张原图读进内存，再完整解码出缩略图。一张 4800 万像素的原图光解码就要大约 140MB，50MB 的上传很可能把内存撑爆。

- **把堆调大**：否——服务器是 2 核 2G，还和 quizzy 共用，没有余量。
- **上限退回 30MB**：否——风险没变，只是换个数字。
- **改后端写法：原图边收边写盘，不再整张放进内存；缩略图用降采样解码，只按目标尺寸读像素**（选定）。堆不加。

**头像存什么**

- **只存裁剪后的小图**：否——主人要能换回以前的头像时重新取景。
- **原图原样保存（不受压缩档影响），另存一张 512px 的方形裁剪结果**（选定）。

**历史头像**

- **只保留最近几张，或只能看不能换回去**：否。
- **全部保留，最新的在前；历史里一项对应一张原图；切回某张要重新裁剪，裁剪框默认停在这张上次的位置；新的裁剪结果覆盖这一项原来的，这一项移到最前面，不另外多出一条**（选定）。当前头像也可以直接重新裁剪。

**裁剪**

- **自动取中间的正方形**：否——主人要自己取景。
- **手动裁剪框：正方形，按圆形预览；手机上拖动加双指缩放，电脑上拖动加滚轮缩放**（选定）。

**头像算不算照片**

- **进相册**：否——相册是看餐照和日记图片的地方。
- **原图和裁剪结果都算进照片空间（[ADR 0013](./0013-photo-storage-and-quota.md)），但不进相册**（选定）。

## Consequences

- 上限原来散在四处：后端上传配置、后端照片校验、前端上传前的检查、前端容器的 nginx。这次一起改，以后后端只认一处配置。
- 头像只在「我的」页页头显示，没设时显示首字母（取自昵称，没昵称就取用户名，见 [ADR 0050](./0050-account-page-password-rename-and-deletion.md)）。
- 历史列表里每一项都是方形格子，**格子里完整显示原图、不裁切**，当前在用的那张加标记；点开就进入原图上的裁剪框。原图也要生成缩略图，否则列表会去拉几十 MB 的原图。
- 从历史里删一张：原图和裁剪结果一起进回收站（[ADR 0047](./0047-trash-snapshot-table.md)），恢复时也一起回来。当前头像也能删，删了就回到首字母，不会自动换成上一张。另有「不用头像」：回到首字母，历史里的都还在。
- 历史头像不限张数，只受照片总空间限制。
- 头像文件和餐照、日记图片放在同一个图片目录里，跟着每日快照一起备份（[ADR 0026](./0026-photo-storage-and-backup.md)）。
