# 餐次条目和饮水记时刻；饮水从每天一个累计数改成一笔一笔记

Status: accepted · 2026-11-21

主人要给三餐、加餐和饮水记一个时刻，可以改，默认是记录的那一刻。条目原来只记了「什么时候点的保存」；饮水每天只存一个累计数，点「−」就是往回减，根本没有单笔，也就没地方挂时刻。

## 决策

1. **时刻记在每条条目上**。记一餐的弹层顶部有一个时刻，这一次加进来的条目都用它。单条条目可以改时刻。一餐里的条目按时刻排，餐次标题显示这一餐最早的时刻。
2. **饮水改成一笔一笔记**：每笔有毫升数和时刻，一天的饮水量是当天各笔之和。点「−」就是撤掉最后一笔。点开饮水卡片能看到当天每一笔，可以改毫升数和时刻，也可以删。删掉的饮水不进回收站。
3. **默认时刻**：记今天，用现在的钟点；补记别的日子，早餐 8:00、午餐 12:00、晚餐 18:00，加餐和饮水用现在的钟点。
4. **旧数据**：旧条目的保存时间和记录日期是同一天的，用保存的钟点当时刻；不是同一天的，时刻留空、不显示。旧的饮水累计数每天迁成一笔，时刻留空。

## Considered Options

**时刻挂在哪一层**

- **每个餐次一天一个时刻**：否。加餐一天可能吃好几次，一个时刻装不下。
- **每条条目一个时刻，同一次加入的共用**（选定）。

**饮水怎么挂时刻**

- **只记当天最后一次喝水的时刻**：否。看不出一天里是怎么喝的，也改不了某一笔。
- **改成一笔一笔记**（选定）。代价是一次数据迁移，饮水的接口也要换。

**补记过去的日子时，默认几点**

- **一律用现在的钟点**：否。凌晨补记昨天的晚饭，会默认成凌晨 4 点。
- **按餐次给默认值**（选定）。

**删掉的饮水进不进回收站**

- **进**：否。太碎了，一笔几百毫升，恢复的价值很低。原来点「−」也是直接没了。
- **不进，直接删**（选定）。回收站的范围（scope #39）不变。

## Consequences

- 需要一次迁移：条目加一列时刻（可空）并按上面的规则回填；新建饮水明细表，把旧的每天累计数迁过去。
- 饮水目标、首页的饮水环、趋势图都改成按当天各笔求和；外部 agent 接口里的饮水口径也跟着改。
- 「时刻」写进术语表，和「什么时候点的保存」分开。

## 修订（2026-11-21）：老条目的时刻改成默认值

上线后主人说，以前的条目多半不是吃的时候记的，「保存时的钟点」不可信，要全部改成默认值。迁移 V48 把 V45 装上之前保存的条目统一改掉：早餐 8:00、午餐 12:00、晚餐 18:00（和补记别的日子的默认值同一套），原来留 NULL 的补记条目也一样填上。加餐没有固定的默认钟点，清空、不显示，不编一个出来。V45 之后的条目时刻是记的时候确认过的，不动。

## 修订（2026-11-23）：三餐改成一餐一个时刻

决策 1 被 [ADR 0062](./0062-main-meal-single-time-and-clearable-time.md) 修订：早午晚三餐一餐一个时刻、整餐共用；加餐仍按条记，可多选批量改。饮水、条目、整餐的时刻都可以清除。
