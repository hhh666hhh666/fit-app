# 会话页暂停与组次净用时落库

Status: accepted

训练中途要休息、接电话，需要让计时停下来，但训练本身不能结束——[ADR 0020](./0020-session-local-persistence-and-wall-clock-timer.md) 刚把会话做成本机持久化的对象，暂停就有地方可放。另一头，每组做完要能看见「这一组花了多久」，这个数字也该留下来供事后复盘节奏，而不是训练一提交就蒸发。

## Considered Options

- **暂停只冻结计时、录入区照旧可改可勾**：否——等于暂停没暂停；而且「暂停期间勾的组，用时算不算暂停段」还要再定义一套剔除算法，容易出歧义。
- **暂停时只锁勾选、允许改数字**：否——多一个「输入框亮着、勾是灰的」的中间态，要记两条不一样的规则，界面上也难表达。
- **暂停合计单独落库并在页面上单独展示**：否——多存一个数字，会引出「跟各组用时之和又对不上」的新问题，收益只是「知道自己休息了多久」。
- **组用时不落库、只在训练中显示**：否——一点「结束训练」用时立刻蒸发，详情页看不到，「记录」就只剩当时看一眼。
- **组用时含暂停（存完成时刻、前后相减）**：否——「各组用时之和」会比页面上的净时长多出一大截，两个数字在同一个页面上就能看出矛盾。
- **编辑过的记录按下标保留旧用时**：否——删掉第 2 组之后，原第 3 组的用时就会跑到第 2 组头上，张冠李戴比没有更糟。
- **暂停＝冻结计时 ＋ 锁住录入区；组用时＝与上一组完成的间隔、剔除暂停段，落库为「该组净用时秒数」；编辑页该字段可改**（选定）。

## Consequences

- 计时与用时统一到「净时间」这一个口径上：`训练净时长 = 真实时间 − 暂停合计`，`组净用时 = 与上一组完成的间隔 − 该区间内的暂停`。所以「各组用时之和」与页面上的净时长同口径，不会互相打架。
- 存储：`workout_set` 加 `duration_sec INT NULL`（迁移 **V21**；NULL＝无用时，涵盖全部历史数据与编辑时新增的组）。暂停区间只存在于本机会话里，提交后只有净结果入库，暂停明细不留。
- 组用时的基线是**全局上一组完成的时刻**（跨动作按实际勾选先后），第一组从开始训练算起；撤回某一组的完成状态后，基线自然回退到剩下最后一个已完成的那组，不需要额外的字段。
- 详情页编辑态把该字段做成可改的「分:秒」文本输入：留空合法（表示这条没有用时），格式或范围不合法则拦下并提示。编辑是**整体覆盖**，没填的行保存后即无用时——这是「重写过的组次不再有真实用时」的诚实表达。
- 暂停按钮落在会话页顶部状态行：整块状态区可点，文案在「训练中」与「已暂停」之间切换，计时在暂停期间冻结在那一刻。
- 前端与数据模型的说明需同步（见 `docs/design/前端.md`、`docs/design/数据模型.md`）。
