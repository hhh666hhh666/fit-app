# 边吃边数：本机进行中计数，开始定餐次，吃完整批记进那一餐

Status: accepted · 2026-11-23

吃饺子这类论个吃的东西，事先不知道会吃多少，靠脑子记容易忘（2026-11-23 主人提出）。做「边吃边数」：吃一个点一下，可以同时数好几种，吃完一起记进某一餐。

## 决策

1. **入口**：长按首页或饮食页对应餐次的按钮，进入这一餐的边吃边数；首页餐次入口第二页「排便」左边放一个明面入口，点开先选餐次（按当前时间预选）。
2. **开始就定餐次**，中途点顶部餐次名可以换，已数的不受影响；日期和时刻取**开始的那一刻**，早午晚餐已有时刻就沿用。
3. **同一时间只有一场**；进行中时首页、饮食页顶部常驻一条进度，点它回来；长按别的餐次时提示先去看正在数的那场。
4. **任何食物都能数**（食物库的和吃过的临时条目）：每点一下＝一个（单位按常用份，没设默认「个」，可换）；「一个多少 g」开始、途中、结束时都能补，「吃完了」之前必须补齐。自己建的食物补了可勾「存为常用份」（默认勾）；预置食物和临时条目只在这次生效。
5. **只存在这台手机上**：App 被杀掉重启还在，换设备看不到；放弃要二次确认。
6. **吃完了**：每种落成一条普通餐次条目（克数＝个数×一个多少 g，按份冻结单位，见 ADR 0066），个数为 0 的跳过，然后清空。
7. **可玩性**：数字滚动、轻震（可关）、随个数堆小圆点（满十并成大的）、每满 10 个小庆祝、总热量跟着跳；系统「减少动效」时只留数字滚动和震动。

## Considered Options

- **存服务端、多设备同步**：否。边吃边数只会在一台手机上进行，多一张表和几个接口换不来什么。
- **吃完才选餐次**：否。主人习惯从「我在吃午饭」开始。
- **只有设了常用份的食物能数**：否。吃的时候不该被「先去补一份多少」挡住，克数随时可补。
- **多场并行**：否。一顿饭只数一次，并行只会让入口和常驻条变复杂。

## Consequences

- 只记今天：饮食页翻到别的日子时长按餐次只提示「边吃边数只记今天」。
- 一种都还没选就离开页面，这一场当没开始，不留常驻条。
- 换手机、清了 App 数据，进行中的计数就没了——这是只存本机的代价。
- 吃完了走新接口 `POST /api/diet/meals/counted`，食物和临时条目一次事务落库；存回常用份是记下之后另发的请求，失败不影响已记下的。
