# 预置数据以数据库为准，迁移脚本不再修改预置

Status: accepted · 2026-11-04

管理端（[ADR 0048](./0048-admin-console-and-preset-archive.md)）上线后，预置食物和预置动作可以在线修改。从这一刻起，**数据库就是预置数据唯一的真相源**：`V5__seed_preset_exercises.sql`、`V13__seed_preset_foods.sql` 只代表初始状态，不再代表当前状态。以后要批量变动，就从管理端导入。

## Considered Options

- **继续用迁移脚本维护预置，管理端只用来救急**：否——迁移脚本按 id 或按名字改数据时，会覆盖管理员在线上做过的修改，而且不会报错。两边各改各的，迟早会冲突。
- **把预置数据放进资源文件，应用启动时同步进库**：否——每次启动都会把线上修改冲掉，等于不许在线修改。ADR 0009 当年也否过这种做法。
- **数据库为准，迁移脚本不再增删改预置行**（选定）。

## Consequences

- 新的迁移脚本可以给预置相关的表**加列**（新列给默认值），但**不写针对具体预置行的增删改**。确实需要整批订正时，就从管理端导出 JSON，改完再导回去。
- 本地新建的库仍然由 V5、V13 灌入初始数据，所以本地的预置数据可能和线上不一样。排查线上数据问题要看线上库或导出文件，不要看迁移脚本。
- `scripts/preset-data/` 下的工程文件只是当年生成 V13 的过程材料，不是现行数据。
- 预置数据随数据库备份（[ADR 0026](./0026-photo-storage-and-backup.md)），不需要另外备份。
