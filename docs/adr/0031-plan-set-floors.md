# 计划目标支持「逐组层数」（爬楼）

Status: accepted

需求：编辑训练计划时要能给爬楼的**每个组次各设层数**（如 20 / 20 / 15 层）。现状是计划侧只存得下组数（`plan_exercise_set` 只有 `reps` / `weight`），有氧动作在编辑页甚至只留一个「组数」输入框——录制侧早有 `workout_set.floors`（[ADR 0025](./0025-cardio-metric-and-floors.md)），计划侧却是空的。目标只是预填默认值（[ADR 0007](./0007-session-set-flow-and-target-weight.md)），没有它，主人在计划里写的强度就只剩一个组数。

## Considered Options

- **复用 `reps` 列存层数**：否——同一个数在两套语义里混用，导出与后续统计分不清「次数」与「层数」，这正是 ADR 0025 否掉过的方案。
- **计划侧只记组数，层数每场临场填**：否——需求原话是「编辑计划时能设」，每次重填等于计划不承担强度。
- **给有氧单开一张目标表**：否——字段与 `plan_exercise_set` 几乎相同，多一张表就多一处级联删除与一处组数真源。
- **`plan_exercise_set` 加 `floors` 列，与 `workout_set` 同构；服务端按动作口径只留对应那套值**（选定）。

## Consequences

- 迁移 V30：`plan_exercise_set.floors`（可空）。**组数仍由行数表达**（[ADR 0027](./0027-plan-per-set-targets.md)），加层数不动这条。
- 服务端归一：`metric = floors` 的动作，落库时 `reps`／`weight` 置 NULL、只信 `floors`；其余动作忽略客户端传来的 `floors`。与录制侧「只信一个口径」同一条纪律，只是这里能存 NULL，不必用占位值。
- 单组层数校验 **1–51102**（主人 2026-10-19 拍定），前后端同一口径；每组可留空，**全空＝只记组数**（合法），不像力量动作那样要求「至少填一项」。
- 编辑页对有氧不再一律「只填组数」：`metric = floors` 铺逐组「层数」行（组数框控制行数、新行沿用上一行、整组填充可用）；纯有氧但口径不是 floors 的动作（将来的跑步之类）仍只记组数。
- 摘要文案：爬楼念「目标 3 组 × 20 层」／「目标 3 组 · 20/20/15 层」，抽在 `utils/plan-target.ts` 一处，编辑页、计划预览弹层、会话页共用。
- 会话页预填：第 i 行取第 i 组的层数（仍可改、不回写计划）；老计划没有层数时该栏留空。
- 历史计划的层数不存在，**不反推**——与 ADR 0025 对历史爬楼场次的处理一致。

> 关联：ADR 0025、ADR 0027、ADR 0007
