# 身体档案：维持「一行五列」不拆表，加编辑与删除，序列按日取最小

Status: accepted

一条身体档案记录＝**一次测定**，体重与四个围度（胸／腰／臀／臂）在同一行里，某项没量就是 null——**不拆成「体重记录」和「围度记录」两种**。记录**可改可删**：点明细行进编辑弹层（复用录入弹层），长按进多选批量删除。测定时刻由 `DATE` 改为 `DATETIME`、精确到分，列表逐条显示到分。**图表序列按日聚合、同一天取最小值**，列表不聚合。

## Considered Options

- **拆成体重记录与围度记录两种，各自增删**：否——实际用法是「一次站上秤、拿起皮尺一起量」，拆开要存两次、「晨起空腹」这类备注要写两遍；且要新增表 ＋ 迁存量数据。围度在**呈现层**拿到与体重对等的待遇（各有列表位置、各有独立图表）就够，不需要在数据层也分开。
- **删除时可以只清体重 / 只清围度**：否——「只清某几项」本质上是**编辑**不是删除；这次补了编辑能力，这个需求由编辑承担，删除就专心删整条。
- **编辑弹层里再放一个「删除这条」**：否——删除入口已定为长按多选，再在弹层里放一个是双入口，且编辑时误触红色删除的代价太大（只是想改个数字）。
- **围度做成一张图四条线**：否——要改公共绘制层 `FtTrendChart`（饮食页五指标也在用，有回归风险，且 ADR 0015 定了「绘制层只留一份」）；更要命的是臂围 ~35 cm 与臀围 ~95 cm 共用一根 y 轴，臂围会被压成平线。改为**一张图 ＋ 部位分段条切换**：每段独立定 y 轴、曲线撑满，组件一行不用改。
- **图表同一天多条取最新 / 取平均**：否——体重的口径已经是「一天里最轻那次最能代表真实体重」（取最小），围度跟它统一，口径只有一套、好解释；围度一天量不了几次，这个选择的实际影响很小，统一比「测量学上最优」更值。
- **维持一行五列 ＋ 编辑整条 ＋ 长按批量删除 ＋ 序列按日取最小**（选定）。

## Consequences

- **序列是日粒度的**，点的 `date` 是 `LocalDate`；**列表是时刻粒度的**，`date` 是 `LocalDateTime`。两处同名不同义，改这两处时要看清。
- 明细列表**不再只查 `weight != null`**——以前只记围度、没记体重的那条在列表里永远不出现，既看不见也删不掉；现在它会出现（体重位空、无差值）。
- 体重卡的大字仍是**最新一条的实测值**（记完立刻看到刚记的数字），不参与按日取最小；「阶段最低 · PR」与「较上周」也仍按原始记录算。即：**卡片看最新，图表看当天最小**——两者不是同一个数，这是有意的。
- 前端给后端的时间串必须是 **ISO 带 `T`**（`2026-10-13T23:51:00`）：`spring.jackson.date-format` 管不到 `LocalDateTime`，空格分隔会 400（口径见 `application.yml` 里那条注释）。
- 存量数据的时分用 `created_at` 的时间分量回填（迁移 V18）——「当天记当天」时它就是最准的估计；用 `00:00` 会让历史全部显示成「某日 00:00」。
- 长按多选删除与训练日志页同一套交互（自绘勾选框、顶栏换操作区、红色 `uni.showModal` 确认）。顺带修了那套交互的一个既有缺陷：H5 上长按后浏览器会补发一次 click，把刚选中的那条又取消掉。
