# 食物组合：固定克数的食物集合，加入时展开为普通条目

Status: accepted

营养模块新增**食物组合**——一串「食物 ＋ 固定克数」的集合（如「减脂早餐 ＝ 燕麦 50g ＋ 鸡蛋 100g ＋ 牛奶 250ml」），记录一餐时可一键整份加入。它解决的是"常年吃同样几样、每次都要重新挑一遍"的重复劳动。

## Considered Options

- **只存食物、不存克数**：否——每次添加仍要逐条填克数，等于没省事。
- **存份数或比例**（1 份燕麦 ＋ 2 个鸡蛋）：否——营养模块只有"克"一个口径，引入"份"是新概念，为自用工具徒增理解成本。
- **组合作为一条汇总条目落库**：否——[ADR 0008](./0008-diet-logging-module.md) 已明确不做"手填一笔总数"；汇总条目要新开一种记录类型，四环口径与条目删除交互都要跟着分叉。
- **只在记录弹层里存与管理组合**：否——没有独立的编辑与删除入口，组合改不动也删不掉。
- **固定克数的食物集合 ＋ 加入时展开为多条普通条目 ＋ 食物库页签管理与弹层横滑条挑选 ＋ 页签手工与弹层「存为组合」两处创建**（选定）。

## Consequences

- 新增食物组合主表与明细行（迁移脚本顺延）。明细行对 `food` 是**弱引用**（食物被删后置空，展示靠名字快照），**加入一餐时读取食物当时的营养**，并按现有口径写入 `meal_log` 快照。
- 「加入组合」＝批量生成 N 条**普通** `meal_log`：营养合计、单条删除、趋势聚合全部沿用现有逻辑，**零新增记录类型**。
- 「存为组合」在前端由当前这一餐已加载的条目直接构造提交，不需要新的后端查询接口。
- 管理入口在食物库页的「组合」页签（列表显示名字、条数、整份热量），可增删改；记录弹层里是一行可横滑的组合卡片，点一下整份加入、可立即撤销。
- 组合不设数量上限、不可嵌套；术语进 `CONTEXT.md`，UI 上一律不用"套餐"（会与「餐次」混淆）。
- 组合的改动**不回溯**已记录的营养——历史是快照，这是既有口径。
