# 主 tab 切换：方向感知的内容层横移，底栏钉住

Status: accepted · 2026-10-21

起因：主人反馈四个主页面之间切换「太生硬」。挡路的不是 CSS，而是导航形态：四页走 `uni.reLaunch`（[ADR 0035](./0035-client-cache-and-invalidation.md) 定的，本轮不动），**旧页在新页挂载之前就已卸载**，框架 `RouterView` 外层也没有 `<Transition>`——DOM 上从来没有一帧同时存在 A、B 两页。所以「A 滑出、B 滑入」的真推拉在当前形态下做不出来，能做的是让**新页按方向入场**。

另一条现状决定了改哪一层：四个页面的结构一致（`.xx` > `.xx__body` 含标题行 ＋ `.xx__bottom` 为 `position: fixed`）。**给页面根元素加 `transform` 会让内部的 fixed 底栏改以根元素为包含块**，底栏会跟着位移、并在位移中露出画布底色。所以要动的是 `__body` 一层，底栏钉住不动。

本卡定的是「切页动效做成什么样、动哪一层、方向怎么传」。它不改导航形态，也不解决滚动位置与日志页月份（那仍归 `docs/todo/2026-10-21-TODO-切页体验后续.md`）。

## Considered Options

- **只做单页淡入微移**：否——四页同一个方向，没有空间关系，只到「不是硬切」，主人诉求里的「翻页感」拿不到。
- **壳页 ＋ 横向 track（四页并排、`translateX(-index × 100vw)`）**：否——上限最高（四页真共存、可加左右滑动手势、`keep-alive` 顺带保住滚动位置），但等于重写导航层：四页现在的文档级滚动要改独立 `scroll-view`、`onPullDownRefresh` 要自实现、`onShow` 取数语义要重建、四页懒加载（各 10~26KB）变成首屏全量。风险面与「加个切换动效」不成比例，留作日后要手势时的整体重构。
- **`tabBar` ＋ `switchTab` 保活**：否——`switchTab` 协议里没有动画参数、`RouterView` 外仍无 `Transition`，想自定义横移得改框架；ADR 0035 已否过一次，H5 下自绘 tabBar ＋ `switchTab` 的保活行为也未实测。
- **底栏跟着一起滑（整屏推）**：否——要底栏位移得把四页的 fixed 换成页内绝对定位并重算占位（首页固定区 440rpx、其余三页 200~240rpx，四页 chrome 高度本就不一致），且旧页已销毁，滑出仍然看不到，白付代价。
- **方向感知横移 ＋ 底栏钉住（选定）**：新页按 `from → to` 的下标差从右或从左入场（`translateX(±18vw)` ＋ `opacity .6→1`），`220ms` / `cubic-bezier(.22,.61,.36,1)`；tabbar 加一条当前项短横，从**上一页那一格**滑到当前格（**用墨黑不用荧光笔**：`$app-highlight` 在白底上对比度约 1.1:1，2px 细线看不见，荧光仍只做内容级高亮）。

## Consequences

- **方向信号是一次性的过场信号，不放 Pinia、不落 storage**（`frontend/src/utils/nav.ts`）：`markTabNav(from)` 在 `uni.reLaunch` 之前调用，目标页 `setup` 里 `takeTabEnter(to)` 取一次并清掉。`reLaunch` 是 SPA 内跳转、不重载 JS，模块级变量足够存活；不放 store 是因为它没有「业务状态」的生命周期，放进去反而要额外回答「什么时候忘掉」。刷新页面时信号为空 → 退化为无方向的淡入，天然安全。
- **只动 `__body`，永不动页面根元素**：四个页面的底栏是根元素的 fixed 子元素，根元素一旦有 `transform` 就会成为它的包含块。这是本方案唯一的硬约束，改页面结构时（比如把弹层塞进 `__body`）要重新核对。
- **底栏指示条是「伪连续」，且方向与内容位移相反**：tabbar 随页面一起重建，旧页已销毁，做不到从上一格的真实位置滑过来。现在先落在**上一页那一格**（`activeIdx ∓ 1`），挂载后双 `rAF` 过渡到当前格。⚠️ 方向是这条最反直觉的地方：首页→日志时内容从**右侧**进场（整个容器在往左移），而指示条要**从左往右**走一格——它标的是「选中哪一格」，不是「内容从哪来」；两者的时间轴一致、行进方向相反才对（踩过一次，把起点写成目标格的右侧一格，看着像倒带）。
- **动效有了 token**（`frontend/src/uni.scss`）：`$dur-fast`（150ms，状态回应）/ `$dur-base`（220ms，位置变化）/ `$ease-out`（iOS 式快出缓收）。此前 `uni.scss` 完全没有动效维度、全站 4 处硬编码，新增动效不再写死值。
- **两处降级**：`App.vue` 全局 `@media (prefers-reduced-motion: reduce)` 关掉入场动画，tabbar 内同时关掉指示条与色变的 `transition`。首页流光卡原有的降级不变。
- **明知的代价**：① 旧页滑出永远看不到，靠方向一致 ＋ 底色骗过眼睛，快速连点时更容易被看穿；② `takeTabEnter` 设 800ms 有效期，超时视为残留、退化为淡入（连点与慢加载的保护）；③ 动画只在页面重建时播一次——从下级页 `navigateBack` 回来页面没重建，不会重播，这是对的；④ **新增主 tab 页面必须记得加两行**（`takeTabEnter` ＋ `:class`），漏了不会报错，只是那一页没有入场动画。
- **不推翻 ADR 0035 的那条否决**：那里的「只补骨架／转场」被否，是因为它想**遮住请求等待**；这里动效有缓存垫底（ADR 0035／0036），做的是**空间关系**，不是为了掩盖白屏。

> 关联：ADR 0035（导航形态与缓存）、ADR 0036（冷启动快照）

> ⚠️ **后续（2026-10-21，0.17.2 修）**：位移期间内容会横向超出页面宽度，而 `body` 那条 `overflow-x: hidden` 管不到 `uni-page-wrapper`——移动端 WebView 把它当成可横向滚动的容器，在视口底部画出一条**全宽 3dp 的灰色横向滚动条**，压在 tabbar 下缘（真机反馈的「底部出现长条」）。补一条到手写约束里：**四个页面根（`.home` / `.log` / `.stats` / `.prof`）必须 `overflow-x: clip`**（`hidden` 兜底老 WebView），只裁不滚，也不影响内部 fixed 底栏——fixed 的包含块是视口，不受祖先 overflow 裁剪。新增主 tab 页面时这个类名要一起加。
