# 管理端：管理员标记、独立网页，预置的删除就是下架

Status: accepted · 2026-11-04

之前预置食物和预置动作只能靠迁移脚本改，线上发现一条数据错了也改不了。现在做一个**管理端**：只给**管理员**用，可以增改预置食物和预置动作，可以下架和重新上架，可以导入导出预置食物，还能看注册用户列表。普通用户这边，预置仍然只读（[ADR 0009](./0009-food-preset-data.md)）。

## Considered Options

**谁是管理员**

- **`.env` 里配管理员用户名**：否——换人要登服务器改配置、重启服务，和 [ADR 0043](./0043-external-agent-read-api.md) 不把令牌放 `.env` 是同一个理由。
- **管理端单独设一个口令**：否——又多一套账号体系，还和用户维度脱钩，审计时说不清是谁改的。
- **用户表加管理员标记，主人的账号用一次性 SQL 标上，界面上不提供授予入口**（选定）。

**管理端放在哪**

- **放进 uni-app 里，只有管理员能看到**：否——45 个营养字段的表单和 1800 多行的表格放在手机屏上很难用，uni-app 也没有像样的桌面表格组件。
- **单独部署一个容器、用一个子域名**：否——2C2G 的机器内存本来就紧（[内存策略](../operations/内存策略.md)），还要多维护一条反代链路。
- **仓库根目录新建 `admin/`（Vue 3 + Element Plus），以桌面浏览器为主，打包后放进现有 web 镜像，从 `/admin/` 访问**（选定）。

**删除预置**

- **直接删掉那一行**：否——食物组合不存营养快照，整份热量按当前食物现算（[ADR 0012](./0012-food-combo.md)），硬删会让组合热量悄悄变少，而且无法恢复。
- **下架后用过的人也看不到**：否——主人组合里用到的食物会从食物库里消失，和组合内容对不上。
- **下架时给每个用过的人真复制一份**：否——重新上架后会出现副本和预置两条，「变回预置」做不到；副本被改过以后也合不回去。
- **下架后用过的人看到的样子和自建食物一样**：否——它看起来是自己的，却不能改；如果允许改，改动又会影响所有人。
- **下架；用过的人仍能看到，带「预置」「已下架」标签，只读，可以复制或自己删掉；重新上架后对所有人恢复**（选定）。

**用户这边的「删除」**

- **不进回收站**：否——App 里其他删除都先进回收站（[ADR 0047](./0047-trash-snapshot-table.md)），这里单独例外会让人摸不着规律。
- **重新上架后用户的删除仍然有效**：否——用户删的是「一条过时的预置」，重新上架后它就不过时了。
- **只对自己隐藏，进回收站，重新上架时作废**（选定）。

## Consequences

**身份与入口**

- 管理端的接口都在 `/api/admin/**`，统一由一处校验：当前用户必须带管理员标记，否则返回「没有权限」。登录沿用 App 的登录接口和 JWT。
- 管理端路由用 hash 模式，和 App 一样不需要 SPA 回退。安卓壳里没有入口。
- 管理端没有改密码、授予或撤销管理员的功能；要改就直接写 SQL。

**下架**

- 预置食物新增下架标记，和动作库现有的 `archived` 是同一种做法。
- **用过**：对食物来说，是这个用户的饮食记录或食物组合引用过它；对动作来说，是训练或计划引用过它。回收站里的记录已经从原表移走，自然不算。
- 没用过的人搜不到它，也不能用它新建记录。用过的人能搜到，可以照常记录，带「预置」「已下架」两个标签，只读。
- 用户删除已下架的预置，只是对自己隐藏：那一行不动，过去的记录和组合照常显示、照常计算。隐藏的条目进回收站，恢复就是取消隐藏，到期或彻底删除后就一直隐藏下去。
- 重新上架会清掉所有用户对它的隐藏，连同回收站里对应的条目一起清掉。

**编辑预置**

- 编辑后，过去的饮食记录不变（有快照）；组合按新数据重算；外部 agent 拿到的完整营养是新值；用户之前「复制为自定义」的副本不变。不做同步或通知。
- 预置食物必填能量、蛋白质、脂肪、碳水、单位和分类，钠可以不填（国标预置本来就有很多没测钠的）。`*` 仍然写在名字后面，由管理员自己加减。名字和其他预置重复时只提示，不拦截。
- 预置动作一旦被任何训练或计划引用过，就锁定记录口径，只能改名称、肌群和排序：改口径会让历史组次的含义变掉（[ADR 0025](./0025-cardio-metric-and-floors.md)）。
- 复制出来的动作是一个全新的动作，PR 和上次数据提示都从零开始。

**导入导出**

- 只做预置食物的导入导出，预置动作不做。导出文件带 id。导入时：带 id 且是预置就更新，不带 id 就新增，id 不存在或不是预置就算无效、跳过。先预检列出新增、更新、无效三类，确认后在一个事务里写入。导入不改上下架状态。

**用户列表**

- 只读：用户名、注册时间、是否管理员、训练次数、饮食条目数、最近一次记录的时间。都从现有数据算出来，不新增字段。禁用和删除用户这次不做（见[待办](../todo/2026-11-04-TODO-管理端后续.md)）。

**已知的不足**

- 收藏和浏览次数仍然存在预置那一行上，全站共用（[待办](../todo/2026-11-04-TODO-管理端后续.md)）。管理端编辑时不会动这两个字段。
