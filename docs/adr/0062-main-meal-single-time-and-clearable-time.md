# 早午晚三餐一餐一个时刻，加餐按条记时刻、可批量改；时刻都能清除

Status: accepted · 2026-11-23

ADR 0059 让每条条目各有一个时刻。用下来主人觉得三餐里一个食物一个时刻太碎：一顿饭就是一个时间点。加餐不一样，一天可能吃好几回，仍要按条记。另外饮水和条目的时刻都只能改、不能清掉。

## 决策

1. **早餐、午餐、晚餐一餐一个时刻**，整餐的条目共用。改时刻只有一个入口：记一餐弹层顶部的时刻，改了整餐一起改；三餐条目的菜单里不再有「修改时刻」。
2. **往三餐里加东西**：这一餐已经有条目，新条目跟着这一餐的时刻（这一餐的时刻被清掉了，新条目也没有时刻）；这一餐还是空的，才按 ADR 0059 的默认规则或弹层顶部选的时刻。服务端也按这条兜底，保证一餐里的时刻始终一致。
3. **加餐每条各有时刻**：单条可以改、可以清；长按进入多选，可以批量改成同一个时刻或批量清除。多选里不放批量删除。
4. **清除时刻**：饮水每一笔、加餐每一条、三餐每一餐都能清；清除后没有时刻，排在最后，显示「—」或不显示。
5. **老数据**：三餐里同一天同一餐各条时刻不一样的，统一成最早的那个（就是餐次标题原来显示的那个）；整餐都没有时刻的不动。

## Considered Options

**三餐的时刻存在哪**

- **新建一张「某天某餐的时刻」表**：否。条目上已经有时刻列，加一张表要同步两处，外部 agent 也要跟着改。
- **仍存在每条条目上，由服务端保证同一餐一致**（选定）。改一餐的时刻就是批量改这一餐的条目。

**加餐要不要也统一**

- **统一成一餐一个**：否。加餐一天几回，统一了就看不出什么时候吃的。
- **按条记，给多选批量改**（选定）。

**清除时刻怎么触发**

- **在「修改时刻」输入框里删空就算清除**：否。太隐蔽，容易误清。
- **单独一个「清除时刻」**（选定）。

## Consequences

- 迁移 V49 统一老数据；接口多一个「改一餐的时刻」和「批量改加餐时刻」，条目和饮水的修改接口多一个「清除时刻」的开关。
- 修订 ADR 0059 的决策 1；术语表「时刻」已改。
