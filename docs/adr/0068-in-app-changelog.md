# App 内更新日志：直接读 CHANGELOG.md，升级后弹一次，管理员可看开发细节

Status: accepted · 2026-11-23

App 是静默自动更新的，主人不知道哪里变了；仓库里的 `CHANGELOG.md` 一直在写，App 里却看不到，连版本号都没有（2026-11-23 主人提出）。在 App 里加「更新日志」。

## 决策

1. **唯一内容源是 `CHANGELOG.md`**：构建时打进前端，不另写一份；「未发布」一节不显示。
2. **入口**：「我的」页最底部一行「更新日志」，右边小字是当前版本。
3. **升级后弹一次**：自动更新后第一次打开，底部弹出这次更新了什么（跨了几个版本就合起来），「知道了」后不再弹。
4. **页面**：版本从新到旧，最新一版展开、更早的折叠成「版本 · 日期 · 改了几处」；新增／改动／修复各配一个色标。
5. **开发细节按身份**：括号里的 ADR 编号、「迁移 Vxx」这类开发字眼，普通账号一律去掉、不能打开；**管理员默认显示**，可以在更新日志页顶部关掉（只记在这台手机上）。去掉只发生在显示时，仓库原文不改。App 因此要知道当前账号是不是管理员——这是 App 里第一处按管理员身份区别显示的地方，管理端仍不在 App 里。

## Considered Options

- **App 里另写一份面向用户的更新说明**：否。两份必然对不上，`CHANGELOG.md` 本来就是大白话。
- **不主动弹，只放入口**：否。静默更新不弹一次，等于没写。
- **所有人都原样显示**：否。ADR 编号对普通用户是噪音。
- **所有人都过滤**：否。主人作为管理员要能顺着编号查到当时为什么这么定。

## Consequences

- 前端镜像的构建上下文只有 `frontend/`，发版流水线先把 `CHANGELOG.md` 拷进去（`frontend/CHANGELOG.md` 已 gitignore）；本地单独 `docker build frontend` 没拷就没有更新日志。
- `CHANGELOG.md` 的写法从此也是给 App 用户看的：保持大白话，开发字眼尽量放进括号里，方便显示时整段去掉。
- `GET /api/account` 多带 `admin`。
- 开发版（版本号 `dev`）不弹升级弹层；第一次装上或从没有更新日志的老版本升上来，只弹当前这一版。
