# 范围

**目的**：判断「某个改动越没越界」的唯一入口。**范围（what）在这里，怎么做（how）在 ADR 与设计文档。**

**读者**：要加功能的人、判断该不该做的人。

**真相源**：本文件（约束表里的 ADR 链接必须指向**当前**结论，漏改 = 索引指旧话）。
⚠️ **改了 ADR 就要回来核对这张表与「明确不做」清单。**

## 定位

- **给谁用**：自用（N=1）。数据模型带用户维度、注册登录先行，为「将来给亲友用」留低成本余地；但不背公开产品的包袱（不做注册风控、内容审核、运营）。
- **解决什么**：健身房训练（力量＋有氧）的记录与复盘——动作库、自建计划、组次录入、训练日志、统计（PR／频次／趋势）、身体档案；数据存自己的服务器，手机端以 Android App 使用。
- **不解决什么**：见下面「明确不做」。

| 35 | 主 tab 导航：四个主页面注册为 **tabBar 页**、切页一律 `uni.switchTab`（页面保活、不再销毁）——切页白屏／滚动位置／日志页月份三件事同时解决；`navigateTo`／`redirectTo` **不能**指向这四个页面。⚠️ H5 不认 `custom: true`，内置 `uni-tabbar` 必须在 `App.vue` 里用样式压掉（含 wrapper 高度复位），**不要改用异步的 `uni.hideTabBar`**（会先闪一拍）；切页动效改 `onShow` 驱动（WAAPI），`reLaunch` 只留给非 tab 页 | 2026-10-21 → [ADR 0038](../adr/0038-tabbar-switchtab-keepalive.md) |
| 36 | 主 tab 切页转场＝**整页快照的连续推拉**：旧页往左滑出、新页从右滑入（反向切页同理），±100% 屏宽 / 300ms；用 View Transitions API 实现——`switchTab` 后框架只让一页在文档里，两页从不共存，只有快照能同时呈现。等新页进 DOM 后**再等一帧**才拍新快照；等待上限 150ms（再久就成「卡住」）。⚠️ 底栏在快照里，会跟着一起滑；不支持 View Transition 的 WebView 退回单页微移入场。⚠️ 页面不可见时浏览器会跳过该特性，**本地 headless 验不了，只能真机看** | 2026-10-21 → [ADR 0039](../adr/0039-view-transition-tab-slide.md) |

## 明确不做

已定的边界——写在这里是为了不再回头纠结，**不是排期中的待办**（含「本阶段不做」与「后置评估」两类，理由列注明）。

| 不做 | 理由 |
|------|------|
| 桌面端独立适配 | uni-app 的 H5 在电脑浏览器直接可用，自用场景足够 |
| 微信小程序 | 自用价值≈0；uni-app 留了可能性，不为其提前买单 |
| iOS 客户端 | 自用设备为 Android；Windows 本机也无法构建 iOS |
| 改密／找回密码／验证码风控 | 收窄到「注册＋登录」（[ADR 0003](../adr/0003-register-login-auth.md)）；将来若给外人用再补 |
| 预设计划模板 | 设计稿定「暂不预设，留扩展空间」 |
| 自动休息计时器 | 后置评估 |
| 休息时长（手动记录） | 2026-10-11 收窄：设计稿无该字段，且第一阶段没有「训练密度」类视图会读它——录了没人看。真要做时是加一列 ＋ 会话页一个输入框的小改动（注意：会话页已有的「组次用时」是**间隔**口径，含组间休息，不是单独记录的休息时长） |
| 磅／英寸单位切换 | 后置评估（2026-10-12 松动：原口径「与营养同批」不再绑定——饮食记录全用克/毫升，单位切换是横切小批，独立再排） |
| AI 从饭菜照片估算营养（拍照识别） | 外部服务有费用且准确率一般；只做「拍照记录」（照片存档，每餐一张）——2026-10-12 饮食记录打磨拍板（[ADR 0008](../adr/0008-diet-logging-module.md)）。⚠️ **包装营养成分表的 OCR 入库不在此列，已放开**——见 [ADR 0018](../adr/0018-food-label-photo-recognition.md) |
| 一键导出全部数据 | 后置评估（先靠服务器定期备份） |
| 小组件／手环直连／真离线／**通知栏常驻通知显示训练计时** | 后置评估；通知栏计时要改安卓壳（原生通知 ＋ 权限）并牵动发布链路，为「锁屏也能看一眼计时」不值——见 [移动端原生能力评估待办](../todo/2026-10-11-TODO-移动端原生能力评估.md) |
| 页内「放弃训练」按钮 | 与「结束训练」语义重叠且位置相邻，长期是持续的小困惑；退出由「结束训练」与「返回＝最小化」共同承担（[ADR 0011](../adr/0011-session-early-finish-and-leave-guard.md)、[ADR 0020](../adr/0020-session-local-persistence-and-wall-clock-timer.md)） |
| 从相册跳到当天的饮食记录 | 相册只管看照片，要看记录去「饮食」页翻（[ADR 0014](../adr/0014-photo-viewer-and-album.md)） |
| 引入第三方图表库（echarts／uCharts） | 为三条折线与一根准星引入约 1 MB 依赖不划算，绘制层自持（[ADR 0015](../adr/0015-diet-trend-zoomable-timeline.md)） |
| 识别确认页的精简表单（只留 4+1＋标签常见项） | 后置优化：先复用完整编辑表单（[ADR 0018](../adr/0018-food-label-photo-recognition.md)）；实测确认成本高再裁 |
| 自动估算训练消耗（按 MET／动作库推算） | 与手填并存时，主人分不清哪个数进了总数；维护一张 MET 表的成本远高于手填一次（[ADR 0029](../adr/0029-daily-energy-and-calorie-gap.md)） |
| 热量缺口的历史曲线与统计 | 缺口是「今天还能吃多少」的即时反馈，做成趋势容易变成盯着数字焦虑；第一版只显示当日值（[ADR 0029](../adr/0029-daily-energy-and-calorie-gap.md)） |
| 服务端数据版本号／ETag／条件请求／增量同步 | 只有手机 App 一个写入端，本机写后失效已等价于「没改动」；加版本号要动全部 VO、部分表结构与请求头，换不来本机能感知的收益（[ADR 0035](../adr/0035-client-cache-and-invalidation.md)） |
| 客户端缓存的定时 TTL 与后台静默校验（SWR） | 会在「什么都没改」时突然重载，与诉求相背；单端写入下没有它要解决的问题（[ADR 0035](../adr/0035-client-cache-and-invalidation.md)） |
