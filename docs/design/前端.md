# 前端

> **移动优先的单前端工程**（`frontend/`）：**uni-app（Vue 3 + TypeScript）** 编译为 H5；Android 装机版由 WebView 壳装载线上 H5（见 [ADR 0002](../adr/0002-android-app-uni-app-shell.md)）。
> 组件库：**wot-design-uni**（easycom 自动引入）；设计语言「训练日志」的变量在 `src/uni.scss`。

**目的**：讲清前端页面的组织方式、状态与服务端数据怎么流转，以及哪些边界容易踩。

**读者**：要改前端的人。

**真相源**：**页面清单与路由以 `src/pages.json` 为准；组件 / 状态 / 请求以 `src/` 代码为准**。本文档只讲边界与约定，不复制那些清单。

> ✅ **设计变量的唯一真相源是 `frontend/src/uni.scss`**——改颜色 / 间距 / 圆角只改它，组件不许写死值（例外：确认为一次性用途的极浅色，如组行表头底色）。
> 视觉系统的人类可读快照是仓根 `DESIGN.md`（从实现派生，不手写）。
> 设计稿（**一次性参照**，不入库）：`.workbuddy/stitch/`——建页时对照 `screen/*.png` 与 `html/*.html`（活稿）。

## 页面与路由

- 页面清单与导航配置都在 `src/pages.json`；页面文件在 `src/pages/<name>/index.vue`
- `globalStyle.navigationStyle` 全站 `custom`——**顶部栏全部自绘**（按各页设计稿）
- 页间跳转：四个主页面（首页 / 日志 / 统计 / 我的）之间用 `uni.reLaunch`；下级页用 `uni.navigateTo`
- 未登录兜底：各页 `onShow`（会话页 `onLoad`）里 `ensureLogin()`——**已落地**，见下文「登录守卫」节
- ⚠️ 路由是 **hash 模式**（`manifest.json` 的 `h5.router`）；本地直达某页用 `http://127.0.0.1:5175/#/pages/<name>/index`
- **第一阶段 13 屏全部落地**（无占位页）：主页／日志／统计／我的／身体档案／计划列表／计划编辑／
  动作库／周安排／会话／汇总／登录／**训练详情**（2026-10-12 补齐，设计稿 `.workbuddy/stitch/screen/detail.png`）
- **第二阶段饮食 5 屏**（2026-10-12，[ADR 0008](../adr/0008-diet-logging-module.md)）：全屏「饮食」页（记录/趋势）／食物库／食物详情／编辑食物／设置——均无设计稿，按现有设计体系自绘；食物库含**系统预置**（只读；列表与记录弹层带「预设」徽标）——2026-10-12 预置批次、2026-10-13 加食物详情页（[ADR 0009](../adr/0009-food-preset-data.md)）
- **2026-10-13 新增「照片」相册页**（[ADR 0014](../adr/0014-photo-viewer-and-album.md)）：`pages/album/index.vue`，入口在「我的」页——网格按日期分组、触底分页、只加载缩略图；配 `components/PhotoViewer.vue`（全屏看图，记录弹层与相册共用）
- 会话页（多动作）的交互口径见 [ADR 0007](../adr/0007-session-set-flow-and-target-weight.md)、[ADR 0010](../adr/0010-session-free-switch-and-early-finish.md)、[ADR 0011](../adr/0011-session-early-finish-and-leave-guard.md)、[ADR 0020](../adr/0020-session-local-persistence-and-wall-clock-timer.md)、[ADR 0021](../adr/0021-session-set-order-and-undo.md) 与 [ADR 0022](../adr/0022-session-pause-and-set-duration.md)：
  按计划目标预填（组数铺行、重量/次数为默认值）、点勾仅标记完成；**动作自由切换**（顶部动作分段条，每格带各组进度，可任意跳转）、全组完成自动切到下一个**未完成**动作；**同一动作内按顺序推进**（前面的组没完成就勾后面的＝静默无反应，不弹提示）；结束训练时若有未完成组先弹确认，**一组都没勾也能结束**（确认文案明说「本次不会有记录」，确认后**清掉这条会话**、不发请求）
- **训练会话存本机**（收在 `src/utils/session.ts`，[ADR 0020](../adr/0020-session-local-persistence-and-wall-clock-timer.md)）：每次变更即 `uni.setStorageSync` 落一份，返回键／后退＝**最小化**——首页「开始训练」按钮正上方出现「训练进行中 · mm:ss」横幅（点它回会话页；不带参数＝接续本机那条），新开会话由首页带 `?fresh=1` 进会话页区分。**计时是墙钟净时长**：`净时长 = 现在 − 开始时刻 − 暂停合计`，页面上的定时器只负责重绘——后台被限速多久都不影响正确性，**别改回「每秒 +1」累加**。点顶部状态区＝暂停／恢复；暂停期间录入区锁住（`pointer-events: none` ＋ 代码层拦截）并压暗。⚠️ **本页不做离页确认**：[ADR 0011](../adr/0011-session-early-finish-and-leave-guard.md) 的 H5 路由守卫（`onBeforeRouteLeave`）已被撤除，别再加回来。⚠️ **结束会话（提交成功、或 0 组确认丢弃）＝先给页面立「已结束」闩、再清本机那份**——页面有三处兜底落盘（变更即存、离页补存、卸载补存），不看这个闩就会把刚清掉的会话原样写回，首页横幅于是永远「训练进行中」；提交成功后用 `redirectTo` 顶掉会话页（不是 `navigateTo`），物理返回不会回到已结束的会话页再提交一份
- 会话页组次操作（[ADR 0021](../adr/0021-session-set-order-and-undo.md)、[ADR 0022](../adr/0022-session-pause-and-set-duration.md)）：**长按组行**弹 `uni.showActionSheet`——未勾的行只有「删除这一组」，已勾的行是「取消完成 / 删除这一组」；取消完成走 `uni.showModal` 二次确认，并**级联取消该动作内后面已勾的组**（保住「已勾的组永远是连续的一段」）；每个动作**至少留一行**。已勾的组行在数值右侧显示这一组的净用时（`formatClock`）。⚠️ **算用时必须「先算后写」，且把本组排除**：`setDurationSec(s, now, row)` 的起点来自 `lastDoneAt()`（全局最新那个已完成组的 `doneAt`），本组一旦先写上 `doneAt` 就会被当成自己的起点、净用时恒为 0（`bb94e42` 起错到 v0.8.2 的 bug）；函数现在带 `self` 参数兜底，**顺序与参数二者都要保留**——只留参数会让语义含糊，只留顺序则一重排就复发

- **计划编辑页的目标与循环组**（2026-10-17，[ADR 0027](../adr/0027-plan-per-set-targets.md)／[ADR 0028](../adr/0028-plan-circuit-groups.md)）：点动作行仍弹底部弹层，但内容换成**逐组列表**——「组数」输入框控制行数（改数字即增删行，新行沿用上一行）、每组一行「次数 / 重量」、一个「整组填充」把第 1 组刷到所有组；组数留空＝不设目标（提交 `sets: []`）。**行摘要的折叠规则抽在 `utils/plan-target.ts`**（与会话页共用，别在两处各写一份）：各组同值→「目标 3 组 × 12 次 · 60 kg」，不同→「目标 3 组 · 12/10/8 次 · 60/65/65 kg」。齿轮入口在**「动作编排」小节行的右端**（顶栏右侧已被「删除」占着），点开高级设置弹层：每行一个「加入循环 / 循环 A」开关 ＋ 组号 A–D；**有氧动作（`muscle === 'cardio'` 或 `metric === 'floors'`）开关置灰**并给提示
- **会话页的循环组**（[ADR 0028](../adr/0028-plan-circuit-groups.md)）：`SessionBlock.circuitNo` 从计划带过来；`circuitSequenceOf()` 现算序列（轮次 × 组内动作，轮数＝组内最大组数，超出某动作组数的轮次跳过），每次现算不缓存——临场加减组要让轮数跟着变。点勾的放行改走 `canComplete()`：循环组内要等序列里**前面的组都完成**（普通动作仍按动作内顺序），完成后**立刻跳到序列下一组**（可能切到别的动作）并 toast「轮到 X 第 n 组」；顶部多一行「循环 A · 第 2/4 轮 · 下一组 B 第 2 组」，分段条用 `scroll-into-view` 自动滚到目标动作。**实际执行顺序不落库**（`workout_block` 仍按动作组织）
- **会话页的本次消耗**（[ADR 0029](../adr/0029-daily-energy-and-calorie-gap.md)）：顶部状态行下面一条常驻细条手填大卡，值存进本机会话的 `calories`（字符串保留输入中间态，空串＝未填），随其他字段「改一次落盘一次」；结束训练时随提交带上（未填不传）。⚠️ 一组都没勾就结束时**不发请求**，所以确认文案要写明「填的消耗也不会计入」
- **饮食页的今日消耗与缺口**（[ADR 0029](../adr/0029-daily-energy-and-calorie-gap.md)）：「已摄入 / 目标」那一行**不动**，下面另起一行「今日消耗 2400 · 缺口 320」（消耗大于摄入＝缺口、反过来＝盈余，**不带正负号**，文案在 `utils/energy.ts` 的 `gapText`）；旁边「怎么算的」开弹层展示服务端返回的算式拆解。档案不全时这一行换成「去补全」入口，**不显示假数字**。数字一律来自 `GET /api/diet`（服务端算），前端不自己乘系数

## 组件与样式边界

- 只用 uni 组件语法（`view` / `text` / `input` 等），**不许用 `div` / `span`**（小程序端不认）
- wot-design-uni 经 easycom 自动引入（`<wd-icon>` 等；配置在 `pages.json`）
- 通用件（卡片 / 主按钮 / 标签 / 表格数字 / 荧光笔高亮 / 空态）定义在 **`App.vue` 全局样式**，前缀 `ft-`；页面私有样式一律 `scoped`
- **数字**（重量 / 次数 / 日期 / 容量）一律加 `ft-num`（表格数字对齐——「训练日志」语言的组成部分）
- **动效目前只有一处，是纯 CSS**（2026-10-21）：首页「训练进行中」横幅的边框流光，照搬 Uiverse「霓虹搜索框」的四层结构。`.resume__glow` / `__dark` / `__white` / `__border` 各是一张比卡片大的圆盘容器（`overflow: hidden` + 圆角），各自的 `::before` 铺一条 `conic-gradient` 并 `rotate` **4s 一圈**，靠 `animation-delay` 负值错开起始相位（-0.67 / -0.78 / -0.91 / -0.92s）；被裁掉后只在卡片边缘露出一条，**模糊度逐层递减**（blur 7 / 3 / 2 / 0.5px）形成「锐边 + 外晕」的层次；内芯 `.resume__inner` 白底压在上面（`z-index: 1`）。配色是原示例的紫 / 品红 / 暗紫 / 淡紫，唯一接 token 的是最锐那层的底色 `$app-ink`——保住原来那条墨黑细边。⚠️ 三条别改：**① `#000` 必须保持 transparent**（原示例铺在黑底上才等于「无色」，搬到浅色页面就是一层灰黑污渍，会把上方「今天 · 计划名」和下方按钮一起压暗）；**② glow 层的外扩不能放大**（原示例 26px 靠深色背景掩盖溢出，这里收到 3px、blur 7px，再大就糊住邻居）；**③ 别换成 JS 定时器**、**别删 `prefers-reduced-motion`**（停转后四层停在各自相位）。全站尚无动效 token，新增动效先按这个口径来，不要另起体系。
- ⚠️ **uni 的 `<input>` 在 H5 渲染为 `<uni-input>` 壳包原生 `<input>`**：脚本驱动测试（CDP / 自动化）填值必须选到**内部原生 input**（如 `.ts__input input`）再 dispatch `input` 事件；对外壳设 `value` 是无效操作（v-model 收不到）。2026-10-11 实测坑。
- ⚠️ **依赖「浏览器接管」的 H5 能力，在 WebView 壳里要壳配合**：`uni.chooseImage`（H5 版）底层是**创建隐藏 `<input type="file">` 再 `click()`**——浏览器会接管这个点击弹出系统选择器，而 **Android WebView 默认不接管、直接吞掉点击**（表现：手机浏览器点「拍照记录这一餐」正常，App 里毫无反应）。必须由壳实现 `WebChromeClient.onShowFileChooser` 才能弹（已实现，见 `android-shell/app/src/main/java/com/fitapp/app/MainActivity.java`）。2026-10-13 实测坑。

## 状态与 API 访问

- 全局状态用 **Pinia**（定义在 `src/stores/`）：`schedule`（计划列表＋周表）、`training`（当前完成的训练详情）、`pick`（动作库点选模式的一次性回传通道）、`diet`（饮食设置缓存：压缩等级/饮水步进/目标）
- HTTP 封装在 `src/api/request.ts`：baseURL `/api`、token 注入（localStorage key **`fitapp_token`**）、401 自动清 token 回登录页、响应信封解包 `unwrap`
- 后端信封：`{ code, message, data, timestamp }`，成功码 `0`（对应后端 `common/Result`）；**后端省略 null 字段**——判断「没值」用 falsy 或 `?? null` 归一，别写 `=== null`
- 各领域的请求按模块拆分到 `src/api/` 下对应文件（`auth` / `exercise` / `workout` / `plan` / `stats` / `body` / `nutrition` / `profile`），不散落在页面里
- **消耗在记录侧的三处展示**（2026-10-17，[ADR 0029](../adr/0029-daily-energy-and-calorie-gap.md)）：① 日志列表行尾在「N 分钟」下面加一行小字「320 大卡」（没填就整行不出现，别用「—」挤那一列）；② 训练详情页三格指标下面一行「消耗 ___ 大卡」，**编辑态是输入框**、留空＝清空（消耗可改是有意的：练完随手填、事后能改）；③ 汇总页在三格下面居中一行「本次消耗 320 大卡」，没填不出现。三处口径都是 `workout.calories`，**不参与**容量、PR 与缺口以外的任何计算。
- 训练记录交互（2026-10-13）：**日志页**长按任一记录进入**多选删除**（勾选/全选/批量删，`POST /api/workouts/batch-delete`），多选态下点行＝切换勾选；「新建训练记录」入口已撤（新建统一走首页「开始训练」）。点记录进**训练详情**页，右上角「编辑」进就地编辑（标题、各组重量/次数、备注，可增删组），按钮变 ✓ 点它保存（`PUT /api/workouts/{id}` 整体覆盖，服务端重算总容量与 PR）；**编辑态多一个「用时」输入**（「分:秒」文本如 `01:42`，留空＝这条没有用时；写法不合法当场拦下，见 [ADR 0022](../adr/0022-session-pause-and-set-duration.md)），只读态在数值右侧逐组显示用时
- **容量口径与有氧**（2026-10-16，[ADR 0023](../adr/0023-volume-metric-scope-and-display.md)／[ADR 0024](../adr/0024-pr-definition-heaviest-set.md)）：有氧动作**不参与容量**——判定来源是后端给的 `WorkoutDetailVO.Block.cardio`（会话页那一份看本机块里的 `muscle`，值来自 `muscleLabel('cardio')`）；有氧块的容量位一律显示 **「—」而不是 0 kg**（会话页底部汇总、汇总页与详情页的三格及动作条目、**日志列表行**、计划列表卡、「我的」页累计；首页「上次训练」卡 2026-10-19 起改口径，见下条）。⚠️ 需要「这次有没有力量动作」的地方，列表项与计划卡由后端给标记（`WorkoutListItemVO.hasStrength`、`PlanListItemVO.lastHasStrength`），**别在前端拿「容量 == 0」当判据**——那样分不清「只有有氧」与「练了力量但重量记 0」
- **有氧专属口径：爬楼按层数**（2026-10-16，[ADR 0025](../adr/0025-cardio-metric-and-floors.md)）：口径声明在动作上（后端 `WorkoutDetailVO.Block.metric`／`ExerciseItem.metric`／计划详情的 `metric`），会话块与详情草稿都要带着它。`metric === 'floors'` 时：会话页组行与详情页编辑只留**一个「层数」输入**（重量／次数是服务端归一过的占位值 0／1，界面不显示）、只读态显示「20 层」、图例写「层数」；「成绩位」统一走 `src/utils/metric.ts`——有力量动作给容量、只有层数给**总层数**、都没有给「—」，**四个页面**（会话页、汇总页、详情页、**日志列表**）共用同一套判断（日志列表的层数合计由后端 `WorkoutListItemVO.totalFloors` 给，2026-10-17 补上——此前那一页只按 ADR 0023 显示「—」，纯爬楼场次的成绩白存了）。⚠️ 老的场次里爬楼的层数是 NULL（无法反推），显示「—」
- **计划卡先预览再开练**（2026-10-19，[ADR 0032](../adr/0032-plan-card-preview-before-start.md)）：`pages/plans` 整卡点击不再进会话页，改弹底部预览弹层（计划名 ＋ 动作清单 ＋ 逐组目标，念法复用 `utils/plan-target.ts`），底部只有「开始训练」「先不练」；**编辑入口仍只有卡片右上「编辑」**（`@click.stop`）。弹层里点开始：本机有进行中的会话先按 [ADR 0020](../adr/0020-session-local-persistence-and-wall-clock-timer.md) 问「继续上次 / 开新的」，**开新会话必须带 `fresh=1`**——此前这一跳没带，点 A 计划会静默接续本机那条旧会话
- **计划的逐组层数目标**（2026-10-19，[ADR 0031](../adr/0031-plan-set-floors.md)）：爬楼（`metric === 'floors'`）在编辑弹层里铺逐组「层数」行（组数框控制行数、新行沿用上一行、整组填充可用；每组可留空、全空＝只记组数，单组 1–51102）；纯有氧但口径不是 floors 的动作仍只记组数。会话页第 i 行预填第 i 组的层数（可改、不回写计划）。摘要文案按 `targetModeOf(metric, muscle)` 选口径：爬楼念「目标 3 组 × 20 层」／「目标 3 组 · 20/20/15 层」

## 登录守卫：逐页的，没有全局钩子

`src/utils/guard.ts` 的 `ensureLogin()` 读 `fitapp_token`，空则 `reLaunch` 登录页并返回 `false`；
每个业务页在 `onShow`（会话页只有 `onLoad`）**首行**写：

```ts
if (!ensureLogin()) return
```

- ⚠️ **必须 `return`**：`reLaunch` 是异步的，不 return 的话本页仍会继续发请求——
  于是「每个接口各 401 一次 ＋ 重复 reLaunch」的老毛病又回来了，守卫等于白加。
- ⚠️ **不在 `App.vue` 的 `onLaunch` 里跳**：那时页面栈还没就绪，`reLaunch` 有时序问题。
- 只验「有没有 token」，**不验有效性**：过期／被服务端拒绝仍靠 `request.ts` 的 401 兜底
  （前端解不开 JWT 的过期时间，除非后端加 `/api/auth/me`）。
- ⚠️ **新建页面记得加这一行**——uni-app 没有页面级 mixin，漏了就是漏了。

- 门禁两条：`npm run typecheck`（vue-tsc）与 `npm run build:h5`（uni build）；CI 的 frontend job 就跑这两条

### 材质语言（本项目「训练日志」口径）

- **面**：纸感底 `$app-canvas`、白卡 `$app-surface`、次级面 `$app-surface-2`；**分隔优先用细线**（`$app-line` / `$app-line-soft`），阴影极克制
