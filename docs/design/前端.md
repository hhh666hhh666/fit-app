# 前端

> **移动优先的单前端工程**（`frontend/`）：**uni-app（Vue 3 + TypeScript）** 编译为 H5；Android 装机版由 WebView 壳装载线上 H5（见 [ADR 0002](../adr/0002-android-app-uni-app-shell.md)）。
> 不用组件库，基础组件是 `src/components/Ft*.vue`；设计语言「晴窗」（[ADR 0041](../adr/0041-design-language-qingchuang.md)），变量在 `src/uni.scss`。

**目的**：讲清前端页面的组织方式、状态与服务端数据怎么流转，以及哪些边界容易踩。

**读者**：要改前端的人。

**真相源**：**页面清单与路由以 `src/pages.json` 为准；组件 / 状态 / 请求以 `src/` 代码为准**。本文档只讲边界与约定，不复制那些清单。

> ✅ **设计变量的唯一真相源是 `frontend/src/uni.scss`**——改颜色 / 间距 / 圆角 / 动效（时长 `$dur-fast` / `$dur-leave` / `$dur-base` / `$dur-slide`，缓动 `$ease-out` 进场 / `$ease-in` 离场 / `$ease-emphasis` 强调）只改它，组件不许写死值，没有例外（CI 的写死颜色守卫硬失败）。
> 视觉系统的人类可读快照是仓根 `DESIGN.md`（`impeccable document` 从实现派生，附带 `.impeccable/design.json`；不手写，过时了重新生成）。
> 没有入库的设计稿：旧的 `.workbuddy/stitch/` 样稿随「训练日志」退役，「晴窗」的样稿是一次性参照的私有 Artifact。新页面照 `DESIGN.md` 的规则和已换皮的同类页面做。

## 页面与路由

- 页面清单与导航配置都在 `src/pages.json`；页面文件在 `src/pages/<name>/index.vue`
- `globalStyle.navigationStyle` 全站 `custom`——**顶部栏全部自绘**（二级页统一用 `FtPageHeader`，主 tab 页自己画页头）
- 页间跳转：**四个主页面是 tabBar 页，互跳一律 `uni.switchTab`**（页面保活、不销毁，[ADR 0038](../adr/0038-tabbar-switchtab-keepalive.md)）；下级页用 `uni.navigateTo`；回 tab 页（如登录成功、汇总页退出）也用 `switchTab`，它顺带清掉非 tab 那整条栈。⚠️ `navigateTo` / `redirectTo` **不能**指向这四个页面，框架会直接拒（`can not navigateTo a tabbar page`）；`switchTab` **不能带参数**。四个主页面之间带**方向感知横移**（[ADR 0037](../adr/0037-tab-switch-transition.md)），方向由 `utils/nav.ts` 在跳转前记下、目标页 `onShow` 取用
- **主 tab 的页面 chunk 是懒加载的**（各页产物 `pages-*-index.js`）：页面虽然保活，但**第一次**切过去仍要现拉 chunk，那一拍里页面还挂不上。所以 `App.vue` 的 `onLaunch` 在首屏稳定后 200ms `import()` 预热另外三页（只取模块，不注册路由、不挂载组件）。⚠️ **新增主 tab 页面时，把它的路径加进那段预热**，否则首次切过去又会闪。
- 未登录兜底：各页 `onShow`（会话页 `onLoad`）里 `ensureLogin()`——**已落地**，见下文「登录守卫」节
- ⚠️ 路由是 **hash 模式**（`manifest.json` 的 `h5.router`）；本地直达某页用 `http://127.0.0.1:5175/#/pages/<name>/index`
- **第一阶段 13 屏全部落地**（无占位页）：主页／日志／统计／我的／身体档案／计划列表／计划编辑／
  动作库／周安排／会话／汇总／登录／**训练详情**（2026-10-12 补齐）
- **第二阶段饮食 5 屏**（2026-10-12，[ADR 0008](../adr/0008-diet-logging-module.md)）：全屏「饮食」页（记录/趋势）／食物库／食物详情／编辑食物／设置；食物库含**系统预置**（只读；列表与记录弹层带「预设」徽标）——2026-10-12 预置批次、2026-10-13 加食物详情页（[ADR 0009](../adr/0009-food-preset-data.md)）
- **2026-10-13 新增「照片」相册页**（[ADR 0014](../adr/0014-photo-viewer-and-album.md)）：`pages/album/index.vue`，入口在「我的」页——网格按日期分组、触底分页、只加载缩略图；配 `components/PhotoViewer.vue`（全屏看图，记录弹层与相册共用）
- 会话页（多动作）的交互口径见 [ADR 0007](../adr/0007-session-set-flow-and-target-weight.md)、[ADR 0010](../adr/0010-session-free-switch-and-early-finish.md)、[ADR 0011](../adr/0011-session-early-finish-and-leave-guard.md)、[ADR 0020](../adr/0020-session-local-persistence-and-wall-clock-timer.md)、[ADR 0021](../adr/0021-session-set-order-and-undo.md) 与 [ADR 0022](../adr/0022-session-pause-and-set-duration.md)：
  按计划目标预填（组数铺行、重量/次数为默认值）、点勾仅标记完成；**动作自由切换**（顶部动作分段条，每格带各组进度，可任意跳转）、全组完成自动切到下一个**未完成**动作；**同一动作内按顺序推进**（前面的组没完成就勾后面的＝静默无反应，不弹提示）；结束训练时若有未完成组先弹确认，**一组都没勾也能结束**（确认文案明说「本次不会有记录」，确认后**清掉这条会话**、不发请求）
- **训练会话存本机**（收在 `src/utils/session.ts`，[ADR 0020](../adr/0020-session-local-persistence-and-wall-clock-timer.md)）：每次变更即 `uni.setStorageSync` 落一份，返回键／后退＝**最小化**——底栏中间圆钮变成「继续」（播放图标，外圈绕一颗流星；四个主页面都有，点它回会话页，不带参数＝接续本机那条；**长按**才弹「继续上次／结束并开新的」二选一弹层 `components/SessionConflictSheet.vue`，开新的还要再确认一次，[ADR 0041](../adr/0041-design-language-qingchuang.md)），新开会话由底栏的选计划弹层带 `?fresh=1` 进会话页区分。**计时是墙钟净时长**：`净时长 = 现在 − 开始时刻 − 暂停合计`，页面上的定时器只负责重绘——后台被限速多久都不影响正确性，**别改回「每秒 +1」累加**。点顶部状态区＝暂停／恢复；暂停期间录入区锁住（`pointer-events: none` ＋ 代码层拦截）并压暗。⚠️ **本页不做离页确认**：[ADR 0011](../adr/0011-session-early-finish-and-leave-guard.md) 的 H5 路由守卫（`onBeforeRouteLeave`）已被撤除，别再加回来。⚠️ **结束会话（提交成功、或 0 组确认丢弃）＝先给页面立「已结束」闩、再清本机那份**——页面有三处兜底落盘（变更即存、离页补存、卸载补存），不看这个闩就会把刚清掉的会话原样写回，底栏圆钮于是永远是「继续」；提交成功后用 `redirectTo` 顶掉会话页（不是 `navigateTo`），物理返回不会回到已结束的会话页再提交一份
- 会话页组次操作（[ADR 0021](../adr/0021-session-set-order-and-undo.md)、[ADR 0022](../adr/0022-session-pause-and-set-duration.md)）：**长按组行**弹 `uni.showActionSheet`——未勾的行只有「删除这一组」，已勾的行是「取消完成 / 删除这一组」；取消完成与删除已勾的组都先确认（`utils/confirm.ts` 的 `ask()`，删除标红；没勾的行只是一行空目标，直接删），取消完成并**级联取消该动作内后面已勾的组**（保住「已勾的组永远是连续的一段」）；每个动作**至少留一行**。已勾的组行在数值右侧显示这一组的净用时（`formatClock`）。⚠️ **算用时必须「先算后写」，且把本组排除**：`setDurationSec(s, now, row)` 的起点来自 `lastDoneAt()`（全局最新那个已完成组的 `doneAt`），本组一旦先写上 `doneAt` 就会被当成自己的起点、净用时恒为 0（`bb94e42` 起错到 v0.8.2 的 bug）；函数现在带 `self` 参数兜底，**顺序与参数二者都要保留**——只留参数会让语义含糊，只留顺序则一重排就复发

- **计划编辑页的目标与循环组**（2026-10-17，[ADR 0027](../adr/0027-plan-per-set-targets.md)／[ADR 0028](../adr/0028-plan-circuit-groups.md)）：点动作行仍弹底部弹层，但内容换成**逐组列表**——「组数」输入框控制行数（改数字即增删行，新行沿用上一行）、每组一行「次数 / 重量」、一个「按第 1 组填满」把第 1 组刷到所有组；组数留空＝不设目标（提交 `sets: []`）。**行摘要的折叠规则抽在 `utils/plan-target.ts`**（与会话页共用，别在两处各写一份）：各组同值→「目标 3 组 × 12 次 · 60 kg」，不同→「目标 3 组 · 12/10/8 次 · 60/65/65 kg」。入口是**「动作编排」卡标题行右端的「循环组」浅底胶囊**（页头右侧已被「删除」占着；有动作进了循环就挂个数），点开循环组弹层：每行一个「加入循环 / 退出循环」开关，进了循环的行下面出组号 A–D 小分段；**有氧动作（`muscle === 'cardio'` 或 `metric === 'floors'`）开关置灰**并给提示
- **会话页的循环组**（[ADR 0028](../adr/0028-plan-circuit-groups.md)）：`SessionBlock.circuitNo` 从计划带过来；`circuitSequenceOf()` 现算序列（轮次 × 组内动作，轮数＝组内最大组数，超出某动作组数的轮次跳过），每次现算不缓存——临场加减组要让轮数跟着变。点勾的放行改走 `canComplete()`：循环组内要等序列里**前面的组都完成**（普通动作仍按动作内顺序），完成后**立刻跳到序列下一组**（可能切到别的动作）并 toast「轮到 X 第 n 组」；顶部多一行「循环 A · 第 2/4 轮 · 下一组 B 第 2 组」，分段条用 `scroll-into-view` 自动滚到目标动作。**实际执行顺序不落库**（`workout_block` 仍按动作组织）
- **会话页的本次消耗**（[ADR 0029](../adr/0029-daily-energy-and-calorie-gap.md)）：顶部状态行下面一条常驻细条手填大卡，值存进本机会话的 `calories`（字符串保留输入中间态，空串＝未填），随其他字段「改一次落盘一次」；结束训练时随提交带上（未填不传）。⚠️ 一组都没勾就结束时**不发请求**，所以确认文案要写明「填的消耗也不会计入」
- **饮食页的今日消耗与缺口**（[ADR 0029](../adr/0029-daily-energy-and-calorie-gap.md)）：「已摄入 / 目标」那一行**不动**，下面另起一行「今日消耗 2400 · 缺口 320」（消耗大于摄入＝缺口、反过来＝盈余，**不带正负号**，文案在 `utils/energy.ts` 的 `gapText`）；旁边「怎么算的」开弹层展示服务端返回的算式拆解。档案不全时这一行换成「去补全」入口，**不显示假数字**。数字一律来自 `GET /api/diet`（服务端算），前端不自己乘系数

## 组件与样式边界

- 只用 uni 组件语法（`view` / `text` / `input` 等），**不许用 `div` / `span`**（小程序端不认）
- **不用组件库**（wot-design-uni 已随「晴窗」移除，[ADR 0041](../adr/0041-design-language-qingchuang.md)）：图标是自带 SVG 的 `components/FtIcon.vue`（24 网格、一套线宽，颜色跟父元素或用 `tone`；新图标往它的表里加一条 path）
- **基础组件** `components/Ft*.vue`：`FtPageHeader`（页头；返回默认 `navigateBack`，父组件写了 `@back` 就交给它，如训练详情编辑中先问「放弃修改？」）、`FtListRow`（列表行）、`FtButton`（primary 橙色只给动作／secondary 玻璃胶囊／ghost／danger 危险红字次要钮）、`FtSheet`（底部弹层）、`FtEmpty`（空状态）、`FtIcon`。全站页面 2026-10-24（0.26.0）换皮完毕
- **页面里的共用形状走 mixin**：玻璃卡、页头胶囊、分段控件、卡片标题、角标、多选操作条、弹层白卡这些形状各页结构差别大、不抽组件；类名（`.glass`、`.pill`、`.seg` …）照旧写在页面的 scoped 样式里，声明体 `@include` `uni.scss` 的 `glass-card`／`glass-pill`／`seg-track`（另有 `-solid`、`-outline`）／`seg-item`／`seg-item-on`／`card-title`／`badge`／`selbar`／`sheet-card`，布局与各页特有的内边距留在页面里。改形状只改 mixin；新页面照抄现有页面的 include 写法
- **按压反馈走 `press` mixin**（2026-10-24，[动效优化待办](../todo/2026-10-24-TODO-动效优化.md)）：`@include press(dim)`（列表行、文字钮、胶囊，按下变暗到 0.7）／`press(shrink)`（实心按钮、圆钮，缩到 0.96）／`press(fill)`（透明钮铺 `$app-surface-2`），写在元素的**基础规则**里，别再手写 `:active`。过渡写在常态上、`:active` 时置 0——按下即时、松手缓 150ms；所以同一个元素上**别另写 `transition`**（会互相盖掉）。按的是整格、缩的是子元素的（首页餐次图标）照同一套数值手写。有禁用态的（多选条的删除钮），禁用规则要排在 press 后面，按住才不会变亮
- ⚠️ **带 `backdrop-filter` 的元素会成为 fixed 子元素的包含块**：玻璃卡片里别放 fixed 弹层（会相对卡片定位）；也别给玻璃层的父级挂 `filter`（背景模糊直接失效）
- **`App.vue` 全局样式**只剩两个类：`ft-num`（数字字体）与 `ft-loading`（加载中占位）；其余通用件一律用 `Ft*` 组件，页面私有样式一律 `scoped`。颜色只认 `uni.scss`：`scripts/check-hardcoded-colors.sh`（CI 同名 job）列出写死的色值，CI 传 `--strict`、有一处就失败（0.26.0 起，全站换皮完、命中清零）
- **JS 里要用的颜色**（Canvas 画图、确认框按钮的 `confirmColor`／`cancelColor`）读不到 SCSS 变量，一律从 `utils/palette.ts` 取：它是 `uni.scss` 几个 token 的镜像，每行行尾注明镜像的 token，`scripts/check-hardcoded-colors.sh` 逐行核对两边一致（对不上就失败，不分告警模式）。新增一项照同样格式写
- **底部弹层**：`FtSheet` 或同一套皮（`MealSheet`、`ComboEditSheet` 自带头部与底部条，没套 `FtSheet`，但遮罩、面板底色、圆角、投影、进出场都照它）——**弹层是实底、不做玻璃**，弹层里的分组用不透明白卡（`$app-surface`）；弹层里最多一个橙色动作（如记录弹层的「添加」）
  - **关法**：点遮罩、右上角关闭钮、按住顶部（把手 ＋ 标题行）往下拉、安卓返回键、电脑 Esc，都走 `FtSheet` 的 `requestClose`（`guard` 先问一句）再发 `close`。遮罩挡住背后页面的滚动。
  - **进出场（2026-10-24 起）**：四个弹层组件（`FtSheet`、`MealSheet`、`ComboEditSheet`、`PhotoViewer`）结构统一成**透明的全屏根容器 ＋ 两个子层**（根 `ft-overlay`；`ft-overlay__hit` 是遮罩的颜色兼点击关闭，`ft-overlay__panel` 是面板；看图是 `ft-overlay--fade` 整层淡），样式集中在 `App.vue`「弹层进出」。进场挂载即播；**离场靠调用处的 `<Transition name="ft-sheet">` 包住 `v-if`**——所以用户关、保存成功后父组件自己关，都是同一个 180ms 加速滑出，退场中不接点击。⚠️ 新加弹层调用处漏了 `Transition` 不会报错，只是关的时候瞬间消失。Vue 只量根元素的时长，根上那条不改值的 opacity 过渡是给它计时的，别删。
  - ⚠️ **进出场只许动 opacity 与 transform**：0.28.0 一度让根元素动 `background-color` 来淡遮罩，整屏每帧在主线程重绘，主人真机反馈弹层进出「生硬、帧率很低」（0.28.1 修）。遮罩的颜色因此放在 `__hit` 层上、动它的 opacity；面板的 `will-change: transform` **只在离场时挂**（`ft-sheet-leave-active`，Vue 隔一帧才起跑，图层先备好），离场第一帧不用临时栅格化整块面板。⚠️ 别改成常驻：它和 transform 一样会让面板成为 fixed 后代的定位基准，面板里套的全屏看图、组合编辑、uni 的 picker 弹窗就只铺满面板（0.28.1、0.28.2 常驻过）。
  - **内容重的弹层进场时不换内容**（`MealSheet`「进场期间不改内容」，2026-10-25）：面板升起的 220ms 里内容一变，就要重排并重新栅格化整块面板。记一餐的做法：列表区定高（不随加载变高）；数据在第一帧前到齐（缓存命中）就随面板一起升，赶不上的等面板停稳再淡入；食物列表先挂 30 行，没有动画在播了再补齐两百行。进场中不显示「加载中」。
  - ⚠️ **点遮罩靠垫在面板底下的 `ft-overlay__hit` 层（它同时是遮罩的颜色），别用 `@click.self`**：uni 在 H5 上包装了事件对象，`target` 与 `currentTarget` 永远不相等，`.self` 一次都不会触发（2026-10-24 改结构时踩到：点遮罩关不掉）。
  - **表单弹层传 `guard`**：面板里冒上来过原生 `input` 事件（＝改过输入框）之后，上面任何一种关法都先问「放弃填写的内容？」。现有五处：记一笔、个人档案、新增动作、目标组次、导入 JSON。`ComboEditSheet`（自带皮的组合编辑表单）自己做了同样的事：加食物是点列表、不打字，听不到 `input`，改成**与打开时的快照比**（组合名 ＋ 各条食物与克数），变了才问；「存为组合」带进来的预填明细算初始状态。
  - **弹层里的滑动不许冒到页面上**：uni 的下拉刷新把触摸监听挂在页面最外层 `uni-page-wrapper`，弹层里的列表滑到顶再往下拉，会被当成拉页面（首页、日志、统计、我的都开着下拉刷新）。`FtSheet`、`MealSheet`、`ComboEditSheet` 的面板一律 `@touchmove.stop`、遮罩 `@touchmove.stop.prevent`；`PhotoViewer` 本来就截着。⚠️ **只截 `touchmove`、别截 `touchstart`**：uni 的长按是靠 window 上的 `touchstart` 模拟的
  - **弹层里的列表要伸出高亮底时放进白卡**：`FtListRow` 的 `highlight` 靠负外边距往两边伸 20rpx；直接放在 `scroll-view` 里会被它的边裁掉（圆角没了、文字像贴着边）。选计划弹层的做法：白卡（`sheet-card` ＋ `overflow: hidden`）包 `scroll-view`，里面再套一层带 28rpx 左右内边距的容器

- **滚动条**：`App.vue` 全局隐藏 `scroll-view` 的滚动条（手机 WebView 本来就是悬浮的，电脑浏览器里那条灰槽会压住卡片右边）；`scroll-view` 里的卡片别用外投影画描边，会被它的边裁掉，改用 `border`

- **动效之三：二级页推入**（`utils/pagePush.ts`，`App.vue` 启动时装上）：拦 `navigateTo` / `redirectTo`，新页整页从右侧 32px 带淡入滑到位（260ms，与切页同长同曲线）；`navigateBack` 回到的页一直保活、不播，主 tab 的 `switchTab` 不经过这里。⚠️ **只动 `transform` 与 `opacity`，播的时候把 `uni-page-body` 临时撑成视口大小的 fixed 框（`inset: 0; overflow: hidden`），播完还原**：二级页多有 fixed 底栏，祖先一带 transform 就以它为定位基准——基准框正好等于视口，底栏就仍在视口底部、跟着整页一起滑，不会跳。新页本来从顶部开始，撑框时内容不跳，上一页留下的窗口滚动也顺手归零（返回时上一页的滚动位置照样恢复）。0.28.x 动的是 `left`，每帧重排 ＋ 重绘整页，高刷屏上帧率上不去。用 MutationObserver 在新页插进文档的微任务里起播，第一帧就在起点，不闪；只在跳转后 1.5 秒内观察。减少动态效果时只淡入。

  - **底栏副本**（2026-10-24）：底栏每页一份，旧页一切走就跟着藏了，新页的要等挂上才画出来——中间那几帧屏幕上没有底栏（真机连拍实锤）。所以切页时把当前底栏也克隆一份钉在 `.tab-slide-pin`（`z-index: 15`，介于克隆层与真底栏之间）补这几帧。⚠️ **副本绝不能和真底栏叠着**：底栏是半透明玻璃，两层一叠边线、投影、圆钮光晕全加倍，整条底栏变色、滑完又跳回来（0.22.1 真机录屏）。所以副本一铺上就把原件 `visibility: hidden`，新页一进文档（放行那一帧，rAF 里、早于绘制）就摘副本、还原件；只有新页 400ms 没来的兜底才把副本留到滑完。实测每个绘制帧恰好一条底栏。副本里的 SVG id 要改名，否则 `url(#id)` 解析到藏起来的原件、投影消失。
  - **层不动、只滑内容**（2026-10-24）：克隆进 `.tab-slide-layer__content`，放行那一帧层撤底色（`is-released`）、只滑内容——层的底色是钉在视口的同一层渐变，整层滑的话光晕会跟着横移。只有兜底放行（新页 400ms 没来、还停在原位）才整层带底色滑走。
  - **滑动期间玻璃不模糊**：`startSlide` 给 `<html>` 挂 `is-tab-sliding`（连点用计数，最后一层摘掉才撤），`uni.scss` 的 `glass` mixin 据此去掉 `backdrop-filter`——两整页玻璃同时在动，逐帧重算模糊是安卓 WebView 最吃力的一刻。⚠️ 新写的会动的玻璃一律 `@include glass`；底栏玻璃不用（它钉着不动，滑动时去模糊反而一闪）。
  - **两层同帧起跑**：克隆层铺上后先不动（层铺着和页面同一层渐变底，挡住底下已就位的新页），由 `playTabEnter` 在新页正文就绪的那一帧放行；新页 400ms 内没来就自己滑。
  - **克隆块按视口位置钉**：每块用 `getBoundingClientRect()` 绝对定位进克隆层，页面滚动不用另算。
  - **只克隆看得见的那一屏**（2026-10-24，`pruneOffscreen`）：整页 `cloneNode` 在长列表上就是点击延迟。克隆后对照原件逐层剪：视口下方的子块直接删，上方的一段换成等高占位块（高度＝首个可见块顶 − 首块顶 − 行间距 − 可见块上外边距）。只剪「从上往下依次排」的容器（块级、纵向从头排的 flex），且上方那段里有行内元素、裸文本、定位元素时不剪——行内元素的框比行框矮，实测会让后面整串上移 2px。画布要在剪之前拷（按序号对应）。实测 80 行列表滚到任意位置，克隆节点 259 → 约 30，可见元素位置误差 ≤0.01px。
  - ⚠️ **克隆体要补继承样式**：它挂在 `body` 下，拿不到全局 `page { font-size; line-height: 1.6 }`（落在 `uni-page-body` 上），行高退回 normal、整页「往上一蹦」。克隆时把原父级的文字类继承属性与 CSS 变量抄过去；**行高要折成无单位倍数**再抄——抄算好的 px 会把所有子元素钉成同一行高。
  - **指示条**：从真实来源格滑到当前格（跨格跳也对），时长缓动与正文共用 `SLIDE_MS` / `SLIDE_EASE`。`<view ref>` 是组件实例，不能在 `FtTabBar` 里判 `animate`，交给 `animateWhenConnected` 取 `$el`；首访时页面 `onShow` 先于 tabbar 挂载，要在 `onMounted` 补播。

  - 克隆层里的 `canvas`（趋势图）`cloneNode` 不带像素，克隆时按顺序 `drawImage` 把当前帧画过去，滑出期间是一张静止截图（2026-10-22 起，以前是空白一闪）。
  - 兜底：动画 `finished` ＋ `SLIDE_MS + 250ms` 定时器双保险摘层，省电模式跳过动画时不能让层留在屏幕上。
- ⚠️ **uni 的 `<input>` 在 H5 渲染为 `<uni-input>` 壳包原生 `<input>`**：脚本驱动测试（CDP / 自动化）填值必须选到**内部原生 input**（如 `.ts__input input`）再 dispatch `input` 事件；对外壳设 `value` 是无效操作（v-model 收不到）。2026-10-11 实测坑。

## 状态与 API 访问

- 全局状态用 **Pinia**（定义在 `src/stores/`）：`schedule`（计划列表＋周表）、`training`（当前完成的训练详情）、`pick`（动作库点选模式的一次性回传通道）、`diet`（饮食设置缓存：压缩等级/饮水步进/目标）
- HTTP 封装在 `src/api/request.ts`：baseURL `/api`、token 注入（localStorage key **`fitapp_token`**）、401 自动清 token 回登录页、响应信封解包 `unwrap`
- 后端信封：`{ code, message, data, timestamp }`，成功码 `0`（对应后端 `common/Result`）；**后端省略 null 字段**——判断「没值」用 falsy 或 `?? null` 归一，别写 `=== null`
- 各领域的请求按模块拆分到 `src/api/` 下对应文件（`auth` / `exercise` / `workout` / `plan` / `stats` / `body` / `nutrition` / `profile` / `diary` …），不散落在页面里
- **取数与缓存**（2026-10-21，[ADR 0035](../adr/0035-client-cache-and-invalidation.md)）：`src/api/cache.ts` 是唯一入口——`read(域, url, params)` 读（命中即零请求），`mutating(域, fn)` 包写操作并在成功后**按域整组作废**。规则三条：① 缓存键＝URL＋参数，存的是 `unwrap` 之后**同一个对象引用**，所以重复赋值不触发重渲染；② 域只有六个——训练（含 `/stats`、`/workouts/totals`）／计划（含 `/plans`、`/schedule`、`/exercises`）／饮食（含 `/diet`、`/settings`，存储占用也在这里）／身体（含 `/body`、`/profile`）／食物（含 `/foods`、`/combos`、识别）／日记（`/diary`）；③ 不设 TTL，条目记下写入时的本机日期，**跨零点自动落空**——`/stats`、不传月份的 `/workouts/month-summary` 这类时间窗口接口靠它，否则第二天早上会看到昨天那段区间算出来的数。
  - ⚠️ **新增写接口必须用 `mutating` 包**。直接调 `request.post`／`put`／`delete` 的症状是「改了不生效」，而且只在切页之后才看得出来。
  - **不进缓存**：分页续页（`offset > 0`）、带搜索词的列表（`q`）、相册列表、识别明细、导出。

## 登录守卫：逐页的，没有全局钩子

`src/utils/guard.ts` 的 `ensureLogin()` 读 `fitapp_token`，空则 `reLaunch` 登录页并返回 `false`；
每个业务页在 `onShow`（会话页只有 `onLoad`）**首行**写：

```ts
if (!ensureLogin()) return
```

- ⚠️ **必须 `return`**：`reLaunch` 是异步的，不 return 的话本页仍会继续发请求——
  于是「每个接口各 401 一次 ＋ 重复 reLaunch」的老毛病又回来了，守卫等于白加。
- ⚠️ **不在 `App.vue` 的 `onLaunch` 里跳**：那时页面栈还没就绪，`reLaunch` 有时序问题。
- 只验「有没有 token」，**不验有效性**：过期／被服务端拒绝仍靠 `request.ts` 的 401 兜底
  （前端解不开 JWT 的过期时间，除非后端加 `/api/auth/me`）。
- ⚠️ **新建页面记得加这一行**——uni-app 没有页面级 mixin，漏了就是漏了。

## 构建与验证

- 门禁两条：`npm run typecheck`（vue-tsc）与 `npm run build:h5`（uni build）；CI 的 frontend job 就跑这两条
- ⚠️ `build:h5` 只剥离类型不做检查——**类型错误只会被 `typecheck` 挡住，构建永远是绿的**
- **视觉验证姿势**：本地 dev（端口 **5175**）起后，用「**750 宽视口**的 headless Chrome」截图得 1:1 完整视图（`--window-size=750,1624`；≤960 视口下 1rpx≈1px）。
  ⚠️ 用更小的窗口（如 390）截会得到「放大溢出」假象（headless 的 window-size 与布局视口不同步），**别拿它判断还原度**。
- ⚠️ **`uni.scss` 新增 token 后要重启 dev 服务器**：它在启动时注入每个组件的样式，热更新不重读；不重启，用到新 token 的页面编译报「Undefined variable」、页面显示「连接服务器超时」（2026-10-24 实测）

### 材质语言（「晴窗」口径，[ADR 0041](../adr/0041-design-language-qingchuang.md)）

- **面**：冷调浅蓝灰渐变底（钉在视口）上放**玻璃面板**（`@include glass` ＋ `$glass-edge` 亮边 ＋ `$glass-shadow`，卡片圆角 `$radius-lg`）；卡内分隔用 `$app-line-soft` 细线，次级面（tag、轨道、灰色按钮）用 `$app-surface-2`
- **橙色只给动作**：开始／继续训练、完成本组、PR、当前组；导航选中态、分段控件、装饰一律不用橙（选中＝深字 ＋ `$app-surface-2` 浅胶囊底，和底栏一套）。**一屏最多一个橙色主按钮**
- **悬浮件**：底栏、会话页汇总条、汇总页「完成」、编辑食物／计划编辑／设置的「保存」、训练详情编辑态的「保存修改」、身体档案的「记录今天的数据」、动作库与身体档案多选的操作条都是贴底悬浮的胶囊，左右 `$tabbar-side`、离底 `$tabbar-gap` ＋ 安全区；⚠️ 正文末尾若有**居中**的元素，要多让出圆钮高出胶囊的那 34px（「我的」页退出登录踩过）
- 具体数值见 `frontend/src/uni.scss`（**单一信息源，本文件不复述数值**）；规则与组件口径的可读版见仓根 `DESIGN.md`
