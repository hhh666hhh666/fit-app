# 前端

> **移动优先的单前端工程**（`frontend/`）：**uni-app（Vue 3 + TypeScript）** 编译为 H5；Android 装机版由 WebView 壳装载线上 H5（见 [ADR 0002](../adr/0002-android-app-uni-app-shell.md)）。
> 组件库：**wot-design-uni**（easycom 自动引入）；设计语言「训练日志」的变量在 `src/uni.scss`。

**目的**：讲清前端页面的组织方式、状态与服务端数据怎么流转，以及哪些边界容易踩。

**读者**：要改前端的人。

**真相源**：**页面清单与路由以 `src/pages.json` 为准；组件 / 状态 / 请求以 `src/` 代码为准**。本文档只讲边界与约定，不复制那些清单。

> ✅ **设计变量的唯一真相源是 `frontend/src/uni.scss`**——改颜色 / 间距 / 圆角只改它，组件不许写死值（例外：确认为一次性用途的极浅色，如组行表头底色）。
> 视觉系统的人类可读快照是仓根 `DESIGN.md`（从实现派生，不手写）。
> 设计稿（**一次性参照**，不入库）：`.workbuddy/stitch/`——建页时对照 `screen/*.png` 与 `html/*.html`（活稿）。

## 页面与路由

- 页面清单与导航配置都在 `src/pages.json`；页面文件在 `src/pages/<name>/index.vue`
- `globalStyle.navigationStyle` 全站 `custom`——**顶部栏全部自绘**（按各页设计稿）
- 页间跳转：四个主页面（首页 / 日志 / 统计 / 我的）之间用 `uni.reLaunch`；下级页用 `uni.navigateTo`
- 未登录兜底：各页 `onShow`（会话页 `onLoad`）里 `ensureLogin()`——**已落地**，见下文「登录守卫」节
- ⚠️ 路由是 **hash 模式**（`manifest.json` 的 `h5.router`）；本地直达某页用 `http://127.0.0.1:5175/#/pages/<name>/index`
- **第一阶段 13 屏全部落地**（无占位页）：主页／日志／统计／我的／身体档案／计划列表／计划编辑／
  动作库／周安排／会话／汇总／登录／**训练详情**（2026-10-12 补齐，设计稿 `.workbuddy/stitch/screen/detail.png`）
- **第二阶段饮食 5 屏**（2026-10-12，[ADR 0008](../adr/0008-diet-logging-module.md)）：全屏「饮食」页（记录/趋势）／食物库／食物详情／编辑食物／设置——均无设计稿，按现有设计体系自绘；食物库含**系统预置**（只读；列表与记录弹层带「预设」徽标）——2026-10-12 预置批次、2026-10-13 加食物详情页（[ADR 0009](../adr/0009-food-preset-data.md)）
- 会话页（多动作）的交互口径见 [ADR 0007](../adr/0007-session-set-flow-and-target-weight.md) 与 [ADR 0010](../adr/0010-session-free-switch-and-early-finish.md)：
  按计划目标预填（组数铺行、重量/次数为默认值）、点勾仅标记完成；**动作自由切换**（顶部动作分段条，每格带各组进度，可任意跳转）、全组完成自动切到下一个**未完成**动作；结束训练时若有未完成组先弹确认

## 组件与样式边界

- 只用 uni 组件语法（`view` / `text` / `input` 等），**不许用 `div` / `span`**（小程序端不认）
- wot-design-uni 经 easycom 自动引入（`<wd-icon>` 等；配置在 `pages.json`）
- 通用件（卡片 / 主按钮 / 标签 / 表格数字 / 荧光笔高亮 / 空态）定义在 **`App.vue` 全局样式**，前缀 `ft-`；页面私有样式一律 `scoped`
- **数字**（重量 / 次数 / 日期 / 容量）一律加 `ft-num`（表格数字对齐——「训练日志」语言的组成部分）
- ⚠️ **uni 的 `<input>` 在 H5 渲染为 `<uni-input>` 壳包原生 `<input>`**：脚本驱动测试（CDP / 自动化）填值必须选到**内部原生 input**（如 `.ts__input input`）再 dispatch `input` 事件；对外壳设 `value` 是无效操作（v-model 收不到）。2026-10-11 实测坑。
- ⚠️ **依赖「浏览器接管」的 H5 能力，在 WebView 壳里要壳配合**：`uni.chooseImage`（H5 版）底层是**创建隐藏 `<input type="file">` 再 `click()`**——浏览器会接管这个点击弹出系统选择器，而 **Android WebView 默认不接管、直接吞掉点击**（表现：手机浏览器点「拍照记录这一餐」正常，App 里毫无反应）。必须由壳实现 `WebChromeClient.onShowFileChooser` 才能弹（已实现，见 `android-shell/app/src/main/java/com/fitapp/app/MainActivity.java`）。2026-10-13 实测坑。

## 状态与 API 访问

- 全局状态用 **Pinia**（定义在 `src/stores/`）：`schedule`（计划列表＋周表）、`training`（当前完成的训练详情）、`pick`（动作库点选模式的一次性回传通道）、`diet`（饮食设置缓存：压缩等级/饮水步进/目标）
- HTTP 封装在 `src/api/request.ts`：baseURL `/api`、token 注入（localStorage key **`fitapp_token`**）、401 自动清 token 回登录页、响应信封解包 `unwrap`
- 后端信封：`{ code, message, data, timestamp }`，成功码 `0`（对应后端 `common/Result`）；**后端省略 null 字段**——判断「没值」用 falsy 或 `?? null` 归一，别写 `=== null`
- 各领域的请求按模块拆分到 `src/api/` 下对应文件（`auth` / `exercise` / `workout` / `plan` / `stats` / `body` / `nutrition`），不散落在页面里
- 训练记录交互（2026-10-13）：**日志页**长按任一记录进入**多选删除**（勾选/全选/批量删，`POST /api/workouts/batch-delete`），多选态下点行＝切换勾选；「新建训练记录」入口已撤（新建统一走首页「开始训练」）。点记录进**训练详情**页，右上角「编辑」进就地编辑（标题、各组重量/次数、备注，可增删组），按钮变 ✓ 点它保存（`PUT /api/workouts/{id}` 整体覆盖，服务端重算总容量与 PR）
- 饮食模块（2026-10-12）：记录弹层 `components/MealSheet.vue` 与四环 `components/FtDietRings.vue` 由首页与「饮食」页共用；**餐照链路**走 `utils/photo.ts`——选图 → canvas 压缩（四档随设置）→ multipart 上传（图片存 MySQL）；显示用 `fetch` + Authorization 转 objectURL（`<img>` 带不了鉴权头），用完 `releasePhotoUrl` 释放
- 食物列表（食物库页与记录弹层）走 **lite 轻量字段 ＋ 服务端搜索**（预置 1800+ 条不全量拉：`listFoods(q, { lite, limit, offset })`）；**食物库页滚动分页**（每页 100 条触底加载、载完显示「共 N 种食物」）、记录弹层取前 200 条；列表**收藏置顶 → 按浏览次数降序**（详情页星标收藏 / 浏览计数）；编辑回填用单条 `getFood(id)`；「复制为自定义」＝跳 `food-edit?copyFrom=<id>` 预填表单、保存走新建（2026-10-12 预置批次；2026-10-13 加分页、浏览计数与收藏）
- 食物交互（2026-10-13）：食物库**点条目进「食物详情」页**（只读：主组固定显示、其余分组只显示有值字段；预置带「预设」标、带 `*` 的名字附来源说明）——右上角**收藏星标**（预置与自有均可，收藏＝列表置顶）；预置的「复制为自定义」沉在**页面最底一行纯文本**（非按钮样式）；自有的底栏「编辑」/「删除」；营养字段表在 `utils/food-fields.ts`（编辑页与详情页共用）；「我的」页食物计数走 `GET /api/foods/count`（精确总数）

## 登录守卫：逐页的，没有全局钩子

`src/utils/guard.ts` 的 `ensureLogin()` 读 `fitapp_token`，空则 `reLaunch` 登录页并返回 `false`；
每个业务页在 `onShow`（会话页只有 `onLoad`）**首行**写：

```ts
if (!ensureLogin()) return
```

- ⚠️ **必须 `return`**：`reLaunch` 是异步的，不 return 的话本页仍会继续发请求——
  于是「每个接口各 401 一次 ＋ 重复 reLaunch」的老毛病又回来了，守卫等于白加。
- ⚠️ **不在 `App.vue` 的 `onLaunch` 里跳**：那时页面栈还没就绪，`reLaunch` 有时序问题。
- 只验「有没有 token」，**不验有效性**：过期／被服务端拒绝仍靠 `request.ts` 的 401 兜底
  （前端解不开 JWT 的过期时间，除非后端加 `/api/auth/me`）。
- ⚠️ **新建页面记得加这一行**——uni-app 没有页面级 mixin，漏了就是漏了。

## 构建与验证

- 门禁两条：`npm run typecheck`（vue-tsc）与 `npm run build:h5`（uni build）；CI 的 frontend job 就跑这两条
- ⚠️ `build:h5` 只剥离类型不做检查——**类型错误只会被 `typecheck` 挡住，构建永远是绿的**
- **视觉验证姿势**：本地 dev（端口 **5175**）起后，用「**750 宽视口**的 headless Chrome」截图得 1:1 完整视图（`--window-size=750,1624`；≤960 视口下 1rpx≈1px）。
  ⚠️ 用更小的窗口（如 390）截会得到「放大溢出」假象（headless 的 window-size 与布局视口不同步），**别拿它判断还原度**。

### 材质语言（本项目「训练日志」口径）

- **面**：纸感底 `$app-canvas`、白卡 `$app-surface`、次级面 `$app-surface-2`；**分隔优先用细线**（`$app-line` / `$app-line-soft`），阴影极克制
- **高亮**：荧光笔 `$app-highlight` 是全站**唯一信号色**——只用于「整块圆角荧光底」式高亮（如 PR 数字）或「当前行左缘短条」（如记录中组的左缘），**一屏最多一处**
- **浮层**（弹层 / 抽屉）：白实底 + 大圆角上角 + 抓手条（见 `rest-sheet` 设计稿）；**本项目不用玻璃拟态**
- 具体数值与用法见 `frontend/src/uni.scss`（**单一信息源，本文件不复述数值**）
